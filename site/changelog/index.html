DSH Desktop 更新日志

版本号是复合形式 <dsh 内核版本>.shell.<壳修订>：内核随官方 @deepseek-ai/dsh 升级，壳修订只包含桌面壳自身的修复与功能。以下节选近期版本要点，完整说明见各版本 Release 页。

v0.2.1-rc.2.shell.7 （内核 0.2.1-rc.2）

  • 小鲸鱼桌宠成为可选的内置扩展：安装包自带未经修改的社区插件 dsh-whale-widget 0.4.2。 插件不需要声明伴随窗口、也不需要提供 pet 路由——壳按已知包版本提供描述，并自己提供一个适配页加载 插件原有的 /dsh-whale/widget.js。打开「桌面设置 → 扩展 → 小鲸鱼桌宠」勾选并点「立即重启」即可： 右下角显示 DeepSeek 余额与今日已用，主窗口最小化后小鲸鱼留在桌面，点右上角 − 或按 Esc 收起。
  • 默认关闭、可随时关闭：whaleWidgetEnabled 缺省为 false；关闭后壳不挂载插件，并移除自己创建的 profile 链接，插件列表、桌面工具面板和伴窗都不再出现该插件。Safe Mode 下一律不挂载。 插件将来若自己声明 dsh.companion，以插件声明为准，壳的适配层自动让位。
  • 署名与上游入口：设置页写明原作者 MeteorNOX，并提供「打开原作者项目」按钮；插件副本固定随壳分发， 不跟随 npm 自动更新。代码为 MIT，美术/音频素材按上游 PROVENANCE.md 原样分发（见 third_party/dsh-whale-widget/VENDORED.md）。
  • 边界不变：壳仍不读 Harness DOM、不调用 executeJavaScript、不提供审批桥；伴窗内的审批动作只会 把用户带回主窗口确认，Safe Mode 与第三方插件隔离承诺保持。
  • 安装包体积：新增约 7 MB 的内置插件资源（角色图、音效、前端脚本）。

v0.2.1-rc.2.shell.6 （内核 0.2.1-rc.2）

  • 插件伴随窗口可用性修复：真实插件（例如小鲸鱼 /dsh-whale/pet）的路由通常经过 Harness 的连接 鉴权栅栏，旧探针用无凭据的 Node fetch 会被 401，导致伴窗永远打不开；现在探针改用主窗口的 session， 看到的结果与伴窗一致。同时修掉「加载慢时晚到的 showInactive() 把已恢复的主窗口重新盖住」的竞态。
  • 透明区域点击穿透：伴窗新增通用 window.dshCompanion.setInteractive()，插件页面可以自己判断指针 是否在自己的 UI 上，让空白区域把点击交给桌面，不再整块挡住 560×620 的范围。窗口默认仍可交互，不实现 这一步的插件行为不变。
  • 升级弹框改跳社区官网：macOS / Linux 的「发现新版本」不再打开 GitHub Release，改为按语言打开社区 下载页（dsh-desktop.com/download / /en/download），按钮文案改为「打开下载页」。
  • 真实插件回归门禁：新增 opt-in 的 pnpm run test:e2e:whale（发现插件 → 最小化开窗 → 审批 fail-closed 唤回主窗口 → 面板重开 → − 恢复），以及 scripts/whale-clickthrough.mjs（真实鼠标事件 验证穿透）。默认 fixture 用例同时补上鉴权栅栏与慢加载竞态。
  • 边界说明：通用壳仍然不读 Harness DOM、不调用 executeJavaScript、不提供审批桥；桌宠里的审批动作 只会把用户带回主窗口确认，不会在伴窗内伪造批准结果。所有判断都在本机完成，不新增联网行为。

v0.2.1-rc.2.shell.5 （内核 0.2.1-rc.2）

  • 插件伴随窗口（ADR 0043）：已安装插件可在自己的 package.json 里声明 dsh.companion { route, width, height, title, showOnMinimize }，主窗口最小化后它的页面会作为独立桌面 窗口留在右下角，恢复主窗口时自动收起。壳只读扫描当前 Web profile 的插件清单，不执行插件代码；显示前 要求该路由 4 秒内返回 2xx text/html，不会留下一块透明残窗。
  • 安全边界：伴随窗口使用 sandbox + contextIsolation、无 nodeIntegration、拒绝 window.open， 导航锁定在声明路径；只转发登录 token。预加载只提供「隐藏自己 / 聚焦主窗口」，壳不读 Harness DOM、 不调用 executeJavaScript、不提供审批桥——审批仍只在主窗口完成。
  • 面板入口：桌面工具面板新增「伴随窗口」分组，列出已声明的伴随窗口并可手动开关；位置跟随主窗口 所在显示器的变化，多个窗口依次错开，退出时销毁。
  • 承接社区需求 #130：小鲸鱼插件只需增加上述声明与 /dsh-whale/pet 路由即可获得该窗口，无需替换 app.asar、无需关闭自动更新。契约见 docs/companion-windows.md。

v0.2.1-rc.2.shell.4 （内核 0.2.1-rc.2）

  • 桌面工具面板点空白关闭：面板打开后点击面板外任意位置即收起；触发按钮的开关与拖动语义不变（#123）。
  • 扩展动作失败不再静默：局域网配对、安全模式、重启 Harness、打开日志、导出诊断、检查更新等操作失败时，面板底部给出「操作未完成：动作名」提示，抛出的异常同样会被捕获（#125）。
  • 飞书未选工作区有字段级提示：扫码创建或保存时，空工作区直接在输入框下方报错、aria-invalid 生效并聚焦到该字段，不再只写页面底部；设置页的工作区行同步显示同一错误（#124）。
  • 工作区选择结果可判别：「取消」保持静默，「目录不可用」明确提示，不再都表现为没反应（#126）。
  • 托盘/菜单失败有系统通知：重启 Harness、局域网配对、打开链接等失败时弹出系统通知并写日志，不再只留在控制台（#127）。
  • 统一失败反馈约定：每个扩展界面各有一条可见的失败通道，渲染在触发动作附近，见 ADR 0042（#128）。

v0.2.1-rc.2.shell.3 （内核 0.2.1-rc.2）

  • Electron 运行时升级到 44.9.1：主进程随之到 Chromium 152.0.7977.167 / Node 24.22.0（与内置 Harness 的 Node 24.21.0 同一条 24 线），用于收上游的安全与稳定性修复。壳的功能、界面与数据目录不变，安装包可直接覆盖升级。
  • 测试工具链到 Playwright 1.64.1：端到端与打包回归与最新驱动保持一致，本版仍跑通 24 项打包回归与四端视觉门禁。
  • 边界说明：内核仍是 0.2.1-rc.2，签名/公证边界与上一版一致；桌面工具面板的 Star 入口只打开仓库页面 （带 ?ref=app-panel 归因），不发送任何遥测。

v0.2.1-rc.2.shell.2 （内核 0.2.1-rc.2）

  • 面板信息组进入四端视觉门禁：桌面工具面板的「信息」组（关于 + 在 GitHub 上 Star）现在由 macOS、Windows、Linux x64、Linux arm64 四个 runner 各产出一张截图，并由门禁强制校验；扩展面契约 从 21 增至 22，任一平台缺少该画面即失败。这样面板里唯一的常驻产品入口不会再被静默改坏。
  • 应用行为无变化：内核仍是 0.2.1-rc.2，本版只推进壳修订号；Star 入口自 .shell.1 起已在面板中， 本版不新增功能，安装包行为与上一版一致。
  • 边界说明：Star 入口只打开仓库页面（带 ?ref=app-panel 归因），不发送任何遥测；签名与公证边界不变。

v0.2.1-rc.2.shell.1 （内核 0.2.1-rc.2）

  • 桌面工具面板新增 Star 入口：信息分组里多了一行「在 GitHub 上 Star」，点击会用默认浏览器打开仓库并带 ?ref=app-panel 归因，方便区分面板点击与官网点击。它只是一个常驻链接：不弹窗、不催促、不影响面板其它操作。
  • 官网同步做了事实与文案迭代：核查并修正了站点上的错误声明（内置运行时是 Node.js 24 而不是 22、去掉已下线的 npx 校验命令、去掉未经核实的插件数量、把 CI 门禁的「真机」措辞改为四端 runner 视觉证据）；修正了中英文各自 独立的文案副本（data-i18n 现在真正生效）；更新日志中英条目逐条对齐；SEO 补齐结构化数据、可抓取的版本快照、 sitemap 日期与双语 404。这些随站点部署，无需更换安装包。
  • 边界说明：Star 入口与官网的 Star 邀请都只打开仓库页面，不发送任何遥测；内核 0.2.1-rc.2、签名与公证边界 与上一版完全一致。

v0.2.1-rc.2.shell.0 （内核 0.2.1-rc.2）

  • 内核升级 0.2.1-rc.1 → 0.2.1-rc.2：同步 32 个 @deepseek-ai/dsh-* peer 版本，重生成 manifest 锁定文件， 并把发行年龄豁免重新固定到新内核（315 → 302 条，13 条保留锁定文件中的解析版本）。两处已复核的壳内补丁 （账号授权弹窗回退、会话回收站生命周期）确认继续适用：被补丁的两个上游 bundle 在 rc.1 与 rc.2 之间 逐字节相同，两个变换在新源码上仍然命中；补丁清单因此改为显式的「已复核内核」列表。
  • 控制套接字路径修复（macOS）：非 legacy 应用的 sidecar 数据目录很深， …/cc-connect/applications/〈应用 ID〉/data/run/api.sock 超过 macOS sun_path 上限，bind 失败后管理器会把 正常工作的连接显示成「已关闭/离线」。现在给 sidecar 一个 $TMPDIR 下的短别名（软链到真实数据目录，零迁移）， 实测深路径 116 字符绑定失败、别名 93 字符成功，打包后日志为 api server started socket=/var/folders/…。
  • 飞书默认改为富卡片：新连接的卡片样式默认 rich、进度展示默认 card（老配置与显式 legacy 选择保持不变）。
  • Linux arm64 产物：发布矩阵新增 ubuntu-24.04-arm，与 amd64 同源打包 -arm64.deb；资产契约从 8 个公开文件变为 10 个 Release 文件（8 个用户可见） （GitHub Release 共 10 个文件，其中 8 个用户可见：安装包 + 校验文件），应用内修复链接按运行架构选择，站点文案与 ADR 0017 同步更新。
  • 发版流程新增四端视觉证据门禁：macOS / Windows / Linux x64 / Linux arm64 四个 runner 在打包 @smoke 跑完后 必须证明渲染出全部 21 个桌面扩展面（首启与安全模式横幅、浮动飞书快捷控制及其底部菜单、飞书管理五种状态、 消息偏好、六个设置面板、LAN 配对、回收站、恢复与加载）；缺失即失败并列出缺哪些，截图随工件发布 （scripts/verify-visual-evidence.mjs）。
  • 边界说明：所有验证都在本地或 CI 的隔离环境完成；健康检查结果只在本地脱敏展示，不会自动上传。
