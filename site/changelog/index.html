DSH Desktop 更新日志

版本号是复合形式 <dsh 内核版本>.shell.<壳修订>：内核随官方 @deepseek-ai/dsh 升级，壳修订只包含桌面壳自身的修复与功能。以下节选近期版本要点，完整说明见各版本 Release 页。

v0.1.6-alpha.2.shell.3 （内核 0.1.6-alpha.2）

  • VC++ 运行库主动检测：Windows 首次启动时检测 Microsoft VC++ 2015-2022 运行库（sharp 等原生组件的依赖），缺失时弹出一次性提示，一键打开微软官方下载页；选择"稍后再说"后本次安装不再打扰。「运行体检」同步新增 Windows 运行库 项，随时可查。
  • 加载失败精确归因：安装或启动报 ERR_DLOPEN_FAILED 时，错误页与导出的诊断报告不再只有原始日志——现在明确指出"缺少 VC++ 运行库或杀毒软件隔离了文件"，并给出官方运行库直链与杀软白名单指引。
  • 安装器中英双语：Windows 安装界面按系统语言自动显示中文或英文（此前默认英文）。
  • 内核与边界不变：内置内核仍为 0.1.6-alpha.2；不新增权限、不改变插件安装与数据目录边界；检测全部在本机完成，不上传任何信息。

v0.1.6-alpha.2.shell.2 （内核 0.1.6-alpha.2）

  • Windows 安装器内容门禁（新增发布 gate）:每个 Windows 安装器在发布前都会被解包核验——内置 node.exe、sharp 原生链(.node + libvips DLL)、闭包完整性清单、mobile-shell、agent-trash-hook 九个关键文件必须存在,其中最高风险的两个二进制(node.exe、sharp .node、libvips DLL)还会对照闭包 SHA-256 清单逐一校验哈希。这把 #39(运行时损坏)与 #56(原生模块加载失败)两类问题的验证从"用户机上发现"提前到"发布流水线拦截"。
  • 诊断经验沉淀:#56 的排查方法(NSIS → 内层 app-64.7z → 逐文件核对哈希)已固化为 scripts/verify-windows-installer.mjs,本地也可运行(node scripts/verify-windows-installer.mjs +安装器路径或 dist 目录),配合 7-Zip 即可复现发布级校验。
  • 内核与边界不变:内置内核仍为 0.1.6-alpha.2;不新增权限、不改变插件安装与数据目录边界。

v0.1.6-alpha.2.shell.1 （内核 0.1.6-alpha.2）

  • 设计体系统一：垃圾桶区块改用与「桌面设置」相同的设计组件——分组卡片、行排版、统一按钮与徽标、真页签（tablist）；条目显示类型徽标、删除时间与「N 天后自动清除」倒计时；空状态为引导卡片，不再是裸 HTML。
  • 不可逆操作加确认：「彻底删除」改为行内两步确认（确认/取消），「清除已过期」同样确认；会话页签的删除按钮改名为「删除（入桶）」——它本来就可还原，旧文案「彻底删除」是误导。
  • 会话页签真实语义：分组展示「已归档 / 未归档」，并说明模型：删除会话先入垃圾桶（30 天内可还原），归档仅在列表中隐藏。
  • 修复：归档会话判定失效：内核工作区注册表把归档列表嵌在 global 字段下，壳只读顶层导致归档会话永远显示为未归档；现兼容两种结构，取消归档的写回也保持内核的 unit 头格式。
  • 修复：内核残留入桶：「恢复内置内核」后，被切走的 overlay 内核目录现在移入垃圾桶（30 天还原窗口），不再永久占用磁盘；移动失败时保持原样，绝不影响恢复本身。
  • 测试网：新增打包 E2E（种子条目还原 → 启动期过期清理断言 → 两步确认清除 → 会话入桶全链贯穿 UI）与契约测试断言（设计体系 class、确认交互、页签语义），让垃圾桶的风格漂移未来能被 CI 拦住。

v0.1.6-alpha.2.shell.0 （内核 0.1.6-alpha.2）

  • 内核升级：随官方 @deepseek-ai/dsh 0.1.6-alpha.2（上一内置内核 0.1.6-alpha.1）。上游变更内容见 官方发布页。
  • 依赖闭包同步：重新生成 lockfile，同步 supply-chain release-age 豁免清单；官方 npm 安全审计零已知漏洞。
  • 闭包安全地板：上游 dsh-office-to-pdf 传递依赖 fflate（GHSA-px8p-9vwx-vf98，恶意 ZIP64 死循环）已按安全地板模式钉到 0.8.3，双树 npm 审计零已知漏洞。
  • 桌面控件挂载适配：适配 0.1.6-alpha.2 内核新的 profile 解析代——桌面控件包的链接同时落在新内核解析的 profile 目录锚点与旧内核兼容锚点（内核 overlay 回滚场景仍可用），打包冒烟（含安全模式故障注入）全绿。
  • 验证：283 项单测、dev E2E 16/16、打包冒烟（真实 Harness UI 渲染 + 安全模式注入）、离线 + 真实市场 E2E、LAN 扫码全部通过。
  • 边界说明：桌面壳无功能变更；社区插件仍不进入安装包。若插件与新内核不兼容，启动失败时错误页提供一键「升级 / 禁用」恢复。

v0.1.6-alpha.1.shell.0 （内核 0.1.6-alpha.1）

  • 内核升级：随官方 @deepseek-ai/dsh 0.1.6-alpha.1（上一内置内核 0.1.5-rc.2）。上游变更内容见 官方发布页。
  • 依赖闭包同步：上游本轮补齐了 dsh-client-ui-sidebar-documentpreview@0.1.6-alpha.1（此前 #48 记录的断链），新内核 peer 缺口 @deepseek-ai/dsh-ptc-runtime 已加入闭包清单；10 个未随新内核发版的 dsh-* 包按解析版本保留，避免版本倾斜。
  • 壳层工具修复：version.mjs bump dsh 的 peer pin 同步此前只发生在内存、从未写盘（本轮首次真实内核升级暴露），已修复并补注册表可用性检查——未发新版的包不再被改写成不存在的范围。
  • 验证：283 项单测、双树 npm 审计零已知漏洞、dev E2E 16/16、打包冒烟（含真实 Harness UI 渲染与 Safe Mode 故障注入）、离线 + 真实市场 E2E、LAN 扫码全部通过；本发布继续执行三平台构建、attestation 核验与跨版本升级门禁。
  • 边界说明：桌面壳无功能变更；社区插件仍不进入安装包。若插件与新内核不兼容，启动失败时错误页提供一键「升级 / 禁用」恢复。

v0.1.5-rc.2.shell.14 （内核 0.1.5-rc.2）

  • 修复闭环：运行体检检出安装损坏时，结果直接附「获取重装包」按钮——按平台与线路（国内 GitCode / 国际 GitHub）一键直达与你当前版本完全一致的安装包下载，并附三步重装指引（退出应用 → 覆盖安装 → 重新体检）；另一条线路作为备用链接并列展示。「导出诊断报告」同步附上直链，贴到 issue 即可定位。
  • 升级矩阵环境感知：残留矩阵在运行时探测构建环境的 Defender 实时保护并记录到输出；仅当保护开启时追加一轮"杀软干扰下损坏→升级"重复验证（S4）。实现中确认 NSIS 卸载器内嵌安装目录（安装树不可克隆），维持逐场景真实安装的正确性优先策略。
  • 内核与边界不变：内置内核仍为 0.1.5-rc.2；不新增权限、不改变插件安装与数据目录边界；体检保持只读、不上传、不自动改写文件。

v0.1.5-rc.2.shell.10 （内核 0.1.5-rc.2）

  • Windows 升级占用拦截：升级安装器启动时检测旧的内置 node.exe 是否仍被占用（正在运行的 Harness、终端等），被占用即弹出中英双语提示"关闭后重试"，不再让复制失败被"忽略"成静默损坏；静默/自动更新场景以明确的退出码失败，而不是装出一个坏升级。
  • Windows 升级残留清理：升级前清除旧安装运行目录的只读/隐藏/系统属性，旧卸载器可以真正删净全部随包文件；只读或被杀毒软件改写过的旧文件不再残留到新版本。
  • 闭包完整性清单：安装包内置全部随包文件的 SHA-256 清单。「运行体检」在原有快速检查之上做全量比对，发现被改动、缺失或多余的文件时直接给出具体文件路径与重装指引；「导出诊断报告」同步收录校验结论，方便贴到 issue 定位。
  • 覆盖场景回归门禁：新增 CI 残留矩阵——预置损坏、只读、占用三类 node.exe 后执行静默升级，断言损坏与只读文件必被替换、占用必须显式失败；闭包校验与篡改检测进入三平台打包冒烟。
  • 工具链修复：根因定位并修复 pnpm ≥10 在本仓库"lockfile 静默不落盘/安装挂死"的问题（版本委托到有缺陷的 pnpm 11.11 所致），包管理器固定为 pnpm 10.33.2；electron-builder 升至 26.16.1；Playwright 升至 1.63.0。
  • 内核与边界不变：内置内核仍为 0.1.5-rc.2；不新增权限、不改变插件安装与数据目录边界；体检保持只读、不上传、不自动修复。

v0.1.5-rc.2.shell.7

  • Electron 44.3.0 + bundled Node 24.21.0 LTS, CI on Node 24.
  • The shell now writes kernel-shared files (profile manifest, Safe Mode overlay and suspects) atomically, eliminating the torn-manifest boot failure behind the Ubuntu Safe Mode smoke family.
  • Adds the Windows NSIS upgrade-residue analysis with a manual verification matrix.
