DSH Desktop 更新日志

版本号是复合形式 <dsh 内核版本>.shell.<壳修订>：内核随官方 @deepseek-ai/dsh 升级，壳修订只包含桌面壳自身的修复与功能。以下节选近期版本要点，完整说明见各版本 Release 页。

v0.1.2-rc.1.shell.7 （内核 0.1.2-rc.1）

  • 桌面垃圾桶：删除的会话、预设和插件都先进垃圾桶，不再一去不返。在 Harness「设置 → 垃圾桶」中查看、按原位置还原（同名冲突自动落副本）、或彻底清除；保留 30 天，过期自动清理。
  • Agent 删除有兜底：Agent 执行的 rm 类删除命令会被桌面版拦截，目标先移入垃圾桶再放行；解析不了或越出工作区、触及 node_modules/.git 的可疑删除直接拦截并说明原因。可在「设置 → 桌面设置」关闭该开关。
  • 插件失败自动隔离：插件导致启动失败时，桌面版自动把问题插件移出启动列表并重启，应用先跑起来；被隔离的插件在恢复横幅中持续可见，升级即自动重新启用。
  • 边界说明：垃圾桶只覆盖桌面版自有资源与被拦截的 Agent 删除；壳外手动删除、系统其它操作不在覆盖范围。隔离与入桶都不删除原始文件，随时可逆。

v0.1.2-rc.1.shell.6 （内核 0.1.2-rc.1）

  • 修复扫码配对后手机提示需要重新认证：内核 0.1.2-alpha.2 起，dsh web 首页只在携带单次启动令牌或签名 cookie 时提供，配对成功后手机加载界面会收到内核的 401（"dsh web authentication required"）。桌面版现在把就绪 URL 中的启动令牌交给配对代理（dsh-mobile-shell 1.0.1），由代理换取签名会话 cookie 并附在转发请求上；内核重启时代理随之自动重启轮换令牌。手机端仍然只对桌面版代理认证，不接触内核令牌。
  • 修复 Windows 右上角按钮重叠：Windows/Linux 的原生最小化/最大化/关闭按钮区域会压住内核会话头部右上角的「Session log」导出按钮。桌面版在该两平台隐藏该胶囊按钮；同样的导出能力仍可通过 /export 斜杠命令使用。
  • 边界说明：代理只对上游出示自己换取的会话 cookie，不向手机下发内核令牌；隐藏按钮不减少任何功能入口。

v0.1.2-rc.1.shell.5 （内核 0.1.2-rc.1）

  • 发布链路自愈：release 或 GitCode 镜像任何一环失败都会自动开 issue（按标题去重，重复失败追加评论），不再出现“官网悄悄停在旧版本、没人知道”。Release 失败后官网数据同步也会照常兜底执行。
  • 一键提交问题：错误页新增「到 GitHub 提交问题」——自动预填版本、平台、内核、安全模式、疑似插件与失败原因，全部脱敏，不含日志原文或路径；诊断报告由你自己导出并拖进 issue，应用不会自动上传任何文件。
  • 升级结果语义修正：插件已是最新可获得版本时，错误页显示「已是当前可获得的最新版本,正在重启…」，不再让人误以为升级失败（registry 元数据可能滞后于刚发布的 dist-tag）。
  • 边界说明：支持入口只在壳自有错误页出现；预填内容不包含密钥、日志或用户路径。

v0.1.2-rc.1.shell.4 （内核 0.1.2-rc.1）

  • 真实世界的失败签名修复：此前失败检测只匹配 failed to apply loader entry，而真实内核断崖（如 0.1.2-rc.1 移除 installSettingsSection）在日志中是 failed to import loader entry——错误页在真实场景下列不出嫌疑插件。现在同时匹配 import 变体与缺失包的 cannot resolve profile bundle 签名，本机实测你遇到的那种崩溃终于能在恢复中心逐个列出插件。
  • 首次启动失败带完整日志：崩溃页不再只有一行 supervisor 摘要，而是携带 harness 自身输出——嫌疑插件的判定依据来源就在这里。
  • 内核断崖提示：错误页按日志证据分类失败原因；识别为「插件引用了内核已移除的导出」时，提示文案直接说明升级插件通常即可修复。诊断报告新增 failure_cause 字段与对应动作建议。
  • 恢复路径真实回归：新增打包级 E2E——预置坏插件 → 崩溃 → 错误页点「升级」→ 真实 npm 安装 → harness 携新插件启动，全程真实 registry。
  • 发布自动化：合并 dsh-bump PR 即自动写发布说明、打 tag、触发完整发布门禁，发布成功自动派发 GitCode 镜像；官网 changelog 页改由发布说明自动生成。
  • 边界说明：恢复操作仍仅限壳自有错误页调用（Harness 页面无法触碰 bundle 清单）；官方内置包不可被升级/禁用。

v0.1.2-rc.1.shell.3 （内核 0.1.2-rc.1）

  • 错误页插件恢复：启动因坏插件失败时，恢复中心现在按包列出可疑插件，并提供「升级」「禁用」与「全部升级并重启」。升级走现有 dsh plugin add 通道拉取 npm 最新版；禁用只从启动 bundle 列表移除，文件保留，可随时在「设置 → 插件」重新启用。官方内置包被明确拒绝，防止误升级破坏与内核的版本锁定。
  • 一键升级解决内核断崖：内核升级导致插件 API 不兼容（如 0.1.2-rc.1 移除 installSettingsSection）时，用户无需再手动翻日志排查——错误页直接给出可操作的修复动作，成功后自动重启。
  • LAN 配对二维码回归保护：新增 E2E 覆盖二维码窗口全链路（代理启动、健康检查、配对码铸造、二维码渲染），验证地址为私网 IP、6 位单次配对码。
  • 边界说明：插件升级需要网络与 npm registry；禁用与升级只触碰用户 profile 的 bundle 清单，不删除插件文件；官方包不在可操作范围内。

v0.1.2-rc.1.shell.2 （内核 0.1.2-rc.1）

  • 首次成功路径：应用内「扩展入口 / 扩展设置」更名为更直白的「桌面工具 / 桌面设置」。主界面新增可关闭、非模态的四步引导：运行环境就绪 → 选择工作区 → 配置模型 → 完成第一条任务；首次任务成功后自动结束，已有成功会话的升级用户不会被重新打扰。
  • 一键运行体检：桌面设置首屏可检查随包 Node/Harness/桌面组件、两个数据目录与磁盘、Harness loopback、Profile、插件市场、安全模式和内核版本。每项显示「正常 / 警告 / 失败」与对应动作。
  • 插件仍然可选：首次引导明确说明无需先装插件；社区插件和插件市场仍由用户主动安装，不进入安装包，也不会静默恢复。
  • 隐私与安全边界：体检默认仅在本地只读执行；代理、registry、更新源连通性只有勾选后才联网。结果不返回路径、URL、日志、代理地址或捕获错误，不上传，也不自动修复用户文件。
  • 发布门禁修正：Windows 跨版本验证结束后的临时目录清理会容忍短暂文件锁，不再把已成功的升级误判为产品失败。

v0.1.2-rc.1.shell.0 （内核 0.1.2-rc.1）

  • 正式候选内核：从 0.1.2-alpha.4 升级并锁定官方 0.1.2-rc.1，包含官方在会话加载、长会话内存与密集实时消息渲染方面的优化，以及新版连接恢复、模型配置和界面改进。
  • 上游同步恢复：修复每日 dsh-watch 缺少 dsh-mobile-shell Web artifact 导致的假失败；后续失败 Issue 只链接真实运行和首个失败步骤，不再默认归因为依赖年龄或上游不兼容。
  • 依赖安全下限：锁定 fast-uri、qs 与 @xmldom/xmldom 的安全版本并重新生成两套锁文件；根依赖与 Harness 生产闭包的官方 npm 安全审计均为零已知漏洞。
  • 边界不变：社区插件仍不进入安装包、不静默安装；dsh-market 继续由用户主动确认安装，Safe Mode 和本地脱敏诊断不改写用户数据。

更早版本的说明见 GitHub Releases。
