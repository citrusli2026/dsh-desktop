DSH Desktop 更新日志

版本号是复合形式 <dsh 内核版本>.shell.<壳修订>：内核随官方 @deepseek-ai/dsh 升级，壳修订只包含桌面壳自身的修复与功能。以下节选近期版本要点，完整说明见各版本 Release 页。

v0.1.5-rc.2.shell.6

  • Electron 44.3.0 + bundled Node 24.21.0 LTS, CI on Node 24; no native rebuilds needed.
  • Adds the Windows NSIS upgrade-residue analysis with a manual verification matrix.

v0.1.5-rc.2.shell.5

  • The floating desktop-tools panel gains a Maintenance group (check for updates, open logs, export diagnostics), completing tool parity across surfaces.
  • The LAN pairing window no longer shows a Windows/Linux menu bar.
  • Kernel bump PRs auto-sync plugin peer pins; the health check reports plugin/kernel compat mismatches; Safe Mode writes its overlay even when the profile crashed before composing; spawn failures explain the reinstall path.

v0.1.5-rc.2.shell.4

  • The agent deletion hook now executes for real, ships in packaged builds, quotes paths safely, and rolls back if the trash index cannot be written.
  • Deletion interception is user-controllable from Desktop settings; toggling it restarts Harness so the hook patch is applied or removed.
  • Supervisor spawn errors after readiness enter the normal restart budget instead of silently stopping.
  • Trash index parsing rejects unsafe ids/paths, and public docs now match the actual trash scope.

v0.1.5-rc.2.shell.3

  • The agent deletion hook now executes for real, ships in packaged builds, quotes paths safely, and rolls back if the trash index cannot be written.
  • Deletion interception is user-controllable from Desktop settings; toggling it restarts Harness so the hook patch is applied or removed.
  • Supervisor spawn errors after readiness enter the normal restart budget instead of silently stopping.
  • Trash index parsing rejects unsafe ids/paths, and public docs now match the actual trash scope.

v0.1.5-rc.2.shell.2 （内核 0.1.5-rc.2）

  • 安全模式恢复更可靠：修复一个首次启动时序问题——Harness 在写入 Profile 清单之前因坏插件崩溃时，安全模式可能枚举不到用户插件而无法自动禁用它。现在崩溃瞬间的插件嫌疑会记录在本地，重启后的安全模式即使读不到清单也能据此生成禁用清单，恢复不再依赖时序运气。
  • 启动失败识别更准：插件因调用新内核 API 而崩溃时（"插件与内核版本不匹配"），错误页会明确提示保持禁用、等待插件适配，避免无效的反复升级。
  • 体检能发现损坏的内置 Node：「一键运行体检」现在校验内置 Node 可执行文件的完整性；升级残留或安全软件改写导致的文件损坏（启动报 spawn 错误）会被直接指出并建议完整重装。
  • 错误页自救指引：内置 Node 启动失败（spawn 错误）时，错误页直接说明文件已损坏/缺失并引导重装（会话与设置保留）；诊断报告也会记录该状态便于求助。
  • 边界说明：局域网配对密钥、设备登记、插件恢复、桌面垃圾桶和诊断仍只保存在本机，不上传用户数据。

v0.1.5-rc.2.shell.1 （内核 0.1.5-rc.2）

  • 启动失败识别更准：修复插件因调用新内核 API 而崩溃时的归类——这类"插件与内核版本不匹配"的崩溃此前不会被识别，错误页不给针对性说明；现在会明确提示保持插件禁用、等待插件适配，避免无效的反复升级。
  • 体检能发现损坏的内置 Node：「一键运行体检」现在校验内置 Node 可执行文件的完整性；升级残留或安全软件改写导致的文件损坏（启动报 spawn 错误）会被直接指出并建议完整重装，不再误报正常。
  • 错误页自救指引：内置 Node 启动失败（spawn 错误）时，错误页直接说明文件已损坏/缺失并引导重装（会话与设置保留），而不是只显示错误码；诊断报告也会记录该状态便于求助。
  • 边界说明：局域网配对密钥、设备登记、插件恢复、桌面垃圾桶和诊断仍只保存在本机，不上传用户数据。

v0.1.5-rc.2.shell.0 （内核 0.1.5-rc.2）

  • 内核升级：随包 Harness 从 0.1.5-rc.1 升至 0.1.5-rc.2，同步全部 31 个直接 peer 契约、锁文件与供应链豁免清单（241 条）。上游为同日快速迭代版本。
  • 边界说明：局域网配对密钥、设备登记、插件恢复、桌面垃圾桶和诊断仍只保存在本机，不上传用户数据。

v0.1.5-rc.1.shell.0 （内核 0.1.5-rc.1）

  • 内核升级：随包 Harness 从 0.1.5-alpha.1 升至 0.1.5-rc.1，同步全部 31 个直接 peer 契约、锁文件与供应链豁免清单（241 条）。
  • 移动接力探测说明：rc.1 的 Web 界面启动时会探测移动接力通道（api/remote.mux）；未开启"连接移动设备"共享时该探测会在开发者控制台留下一条连接拒绝消息，页面功能不受影响。
  • 边界说明：局域网配对密钥、设备登记、插件恢复、桌面垃圾桶和诊断仍只保存在本机，不上传用户数据。

更早版本的说明见 GitHub Releases。
