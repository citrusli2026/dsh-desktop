DSH Desktop 更新日志

版本号是复合形式 <dsh 内核版本>.shell.<壳修订>：内核随官方 @deepseek-ai/dsh 升级，壳修订只包含桌面壳自身的修复与功能。以下节选近期版本要点，完整说明见各版本 Release 页。

v0.1.7-rc.1.shell.3 （内核 0.1.7-rc.1）

  • 修复左下角 DeepSeek 账号菜单中的内置登录：获取授权地址后自动交由系统浏览器打开，并保留当前主题。
  • 每次登录尝试最多自动打开一次授权地址；登录仍由 Harness 账号流程处理。

v0.1.7-rc.1.shell.2 （内核 0.1.7-rc.1）

  • 修复内核 0.1.7 迁移 settings.yaml 后，原生菜单、窗口标题、托盘和通知语言回退的问题；优先从本地 web profile 读取语言与主题，并跟随 profile 更新。
  • 保留对旧 settings.yaml 和 .imported 归档的兼容，读取归档时不会重建旧文件；偏好只保存在本机。
  • 修正跨版本升级门禁：先在旧版首次启动前播种用户设置，再验证旧版迁移和新版安装都保留数据，避免测试夹具制造不真实的混合状态。

v0.1.7-rc.1.shell.1 （内核 0.1.7-rc.1）

  • 修复内核 0.1.7 迁移旧版设置后，原生菜单、窗口标题、托盘等桌面界面语言回退到操作系统语言的问题。壳现在优先读取 web profile 中的语言和主题偏好，并跟随 profile 更新。
  • 保留迁移兼容：仍可读取现存的 settings.yaml 及内核归档的 settings.yaml.imported；读取旧归档时不会重新创建旧设置文件。
  • 偏好留在本机 Harness profile 中，不会上传。

v0.1.7-rc.1.shell.0 （内核 0.1.7-rc.1）

  • 内核升级：随官方 @deepseek-ai/dsh 0.1.7-rc.1（上一内置内核 0.1.6-alpha.2，直接跨到 rc 线）。上游变更内容见 官方发布页。
  • 内核行为变化（对用户可见）：0.1.7 起内核对损坏的社区插件改为「隔离并继续启动」，插件不再拖垮整个 Harness；设置文件无损迁移（旧文件逐字节归档为 .imported）；设置入口移至左下角账号弹层。壳的启动冒烟、升级数据保留断言与设置导航 E2E 均已按新契约更新（随 v0.1.6-alpha.2.shell.4 入库，本轮首次随内核发版验证）。
  • 依赖闭包同步：重新生成 lockfile，同步 supply-chain release-age 豁免清单；官方 npm 安全审计零已知漏洞。新内核 peer 缺口 dsh-client-store、dsh-deepseek-account 已加入闭包清单（audit 门指认）；未随 rc.1 发版的 dsh-* 子包按解析版本保留，无版本倾斜。
  • 边界说明：桌面壳无功能变更；社区插件仍不进入安装包。若插件与新内核不兼容，启动失败时错误页提供一键「升级 / 禁用」恢复。
  • 已知行为变化：内核 0.1.7 将 settings.yaml 无损迁移（归档为 .imported）后，壳的原生界面语言（菜单/托盘/通知）改随操作系统语言，应用内语言选择暂不跨重启保留——后续版本将改为读取内核新设置存储（#68）。

v0.1.7-alpha.2.shell.0 （内核 0.1.7-alpha.2）

  • 内核升级：随官方 @deepseek-ai/dsh 0.1.7-alpha.2（上一内置内核 0.1.6-alpha.2）。上游变更内容见 官方发布页。
  • 依赖闭包同步：重新生成 lockfile，同步 supply-chain release-age 豁免清单（12 个未随新内核发版的 dsh-* 包按解析版本保留，无版本倾斜）；官方 npm 安全审计零已知漏洞。
  • 依赖闭包同步：新内核 peer 缺口 dsh-client-store、dsh-deepseek-account 已加入闭包清单（audit 门指认，与 0.1.7-alpha.1 预演一致）。
  • 内核行为变化（对用户可见）：0.1.7 起内核对损坏的社区插件改为「隔离并继续启动」，插件不再拖垮整个 Harness；设置文件无损迁移（旧文件逐字节归档为 .imported）；设置入口移至左下角账号弹层。壳的启动冒烟、升级数据保留断言与设置导航 E2E 均已按新契约更新（随 v0.1.6-alpha.2.shell.4 入库，本轮首次随内核发版验证）。
  • 边界说明：桌面壳无功能变更；社区插件仍不进入安装包。若插件与新内核不兼容，启动失败时错误页提供一键「升级 / 禁用」恢复。
  • 已知行为变化：内核 0.1.7 将 settings.yaml 无损迁移（归档为 .imported）后，壳的原生界面语言（菜单/托盘/通知）改随操作系统语言，应用内语言选择暂不跨重启保留——后续版本将改为读取内核新设置存储（#68）。

v0.1.7-alpha.1.shell.0 （内核 0.1.7-alpha.1）

  • 内核升级：随官方 @deepseek-ai/dsh 0.1.7-alpha.1（上一内置内核 0.1.6-alpha.2）。上游变更内容见 官方发布页。
  • 依赖闭包同步：重新生成 lockfile，同步 supply-chain release-age 豁免清单；官方 npm 安全审计零已知漏洞。
  • 依赖闭包同步：新内核 peer 缺口 dsh-client-store、dsh-deepseek-account 已加入闭包清单（audit 门指认）；12 个未随新内核发版的 dsh-* 包按解析版本保留，无版本倾斜。上游 0.1.7-alpha.1 内部曾引用未发布的 dsh-terminal@0.1.7-alpha.2，npmmirror 稍后补齐，巡检按 §51 轮询后确认可解析。
  • 内核行为变化（对用户可见）：0.1.7 起内核对损坏的社区插件改为「隔离并继续启动」，插件不再拖垮整个 Harness；壳的启动冒烟已按新契约更新。
  • 验证：296 项单测、双树审计零已知漏洞、dev E2E 16/16、打包冒烟（真实渲染 + 安全模式故障注入 + 闭包校验）、离线/真实市场 E2E（含真实 dshmarket 安装与版本核对）、垃圾桶 UI E2E、LAN 扫码全部通过。
  • 边界说明：桌面壳无功能变更；社区插件仍不进入安装包。若插件与新内核不兼容，启动失败时错误页提供一键「升级 / 禁用」恢复。

v0.1.6-alpha.2.shell.4 （内核 0.1.6-alpha.2）

  • 局域网入口支持 VPN 虚拟网卡（Tailscale / ZeroTier 等）：CGNAT 段 100.64.0.0/10 现在被视为合法局域网地址——此前即使通过 DSH_LAN_IP 显式指定也会被拒绝。自动探测顺序保持物理网卡（Wi-Fi/以太网）优先，没有物理网卡可达时自动使用 Tailscale/ZeroTier 等 VPN 虚拟网卡；同一虚拟网内的手机扫码即可进入 Harness。
  • 测试健壮性：打包 E2E 的设置页导航适配多版内核 UI（含 0.1.7 的账号弹层入口），升级冒烟接受 0.1.7 的设置文件迁移契约（settings.yaml → .imported 逐字节归档），为下一版内核升级铺路。
  • 内核与边界不变：内置内核仍为 0.1.6-alpha.2；不新增权限、不改变数据目录边界。

v0.1.6-alpha.2.shell.3 （内核 0.1.6-alpha.2）

  • VC++ 运行库主动检测：Windows 首次启动时检测 Microsoft VC++ 2015-2022 运行库（sharp 等原生组件的依赖），缺失时弹出一次性提示，一键打开微软官方下载页；选择"稍后再说"后本次安装不再打扰。「运行体检」同步新增 Windows 运行库 项，随时可查。
  • 加载失败精确归因：安装或启动报 ERR_DLOPEN_FAILED 时，错误页与导出的诊断报告不再只有原始日志——现在明确指出"缺少 VC++ 运行库或杀毒软件隔离了文件"，并给出官方运行库直链与杀软白名单指引。
  • 安装器中英双语：Windows 安装界面按系统语言自动显示中文或英文（此前默认英文）。
  • 内核与边界不变：内置内核仍为 0.1.6-alpha.2；不新增权限、不改变插件安装与数据目录边界；检测全部在本机完成，不上传任何信息。

更早版本的说明见 GitHub Releases。
