DSH Desktop 更新日志

版本号是复合形式 <dsh 内核版本>.shell.<壳修订>：内核随官方 @deepseek-ai/dsh 升级，壳修订只包含桌面壳自身的修复与功能。以下节选近期版本要点，完整说明见各版本 Release 页。

v0.1.5-alpha.1.shell.0 （内核 0.1.5-alpha.1）

  • 内核升级：随包 Harness 从 0.1.3-alpha.2 升至 0.1.5-alpha.1，同步全部 31 个直接 peer 契约、锁文件与供应链豁免清单。内核本版重构了会话持久化与终端子系统（新增 dsh-terminal、dsh-fs-local、dsh-session-projection 等子包）。
  • 会话锁原生化简化：新内核改用预编译的 @deepseek-ai/node-addon-system（稳定 Node-API，跨 ABI 兼容）承担文件锁，不再依赖需要按 Node ABI 重编译的 fs-ext。桌面壳的原生重建门禁改为按锁文件判定：内核仍携带 fs-ext 时照旧重编译并执行独占锁探针；内核不再携带时自动跳过；锁文件仍要求而闭包缺失时照旧报错拦截。
  • 边界说明：局域网配对密钥、设备登记、插件恢复、桌面垃圾桶和诊断仍只保存在本机，不上传用户数据。

v0.1.3-alpha.2.shell.0 （内核 0.1.3-alpha.2）

  • 内核升级：随包 Harness 从 0.1.2-rc.1 升至 0.1.3-alpha.2，并同步完整的直接 peer 契约与锁文件。
  • 会话持久化兼容：审查并精确放行新内核所需的 fs-ext 文件锁模块；部署后强制使用随包 Node 22 重编译，并执行真实独占锁/解锁探针，避免开发机 Node 24 产物在安装包内因 ABI 不匹配而启动崩溃。
  • 模拟器测试收敛：Android 专用端到端测试会修复 AVD 快照偶发丢失的 10.0.2.2 默认路由，再验证扫码配对、前后台切换、共享重启和桌面应用重启后的会话续用；不会修改物理设备网络。
  • 边界说明：局域网配对密钥、设备登记、插件恢复和诊断仍只保存在本机，不上传用户数据。

v0.1.2-rc.1.shell.10 （内核 0.1.2-rc.1）

  • 修复手机会话在桌面重启后失效：LAN 代理不再每次启动都更换设备会话签名密钥。配对过的手机可以跨共享停止/重开、Harness 恢复和桌面应用完整重启继续使用，无需重复输入配对码。
  • 修复打包环境中的设备状态存储位置：签名密钥与设备登记迁移到 Electron userData 的 lan/ 私有目录，密钥权限收紧为仅当前用户可读写，不再尝试把设备状态写入随包资源目录。
  • 补齐模拟器和支持诊断：新增 Android 15 模拟器真实 Chrome 的端到端门禁，覆盖配对、后台恢复、共享重启和桌面重启；诊断报告增加不含密钥/配对码的 LAN 状态，Issue 模板也能直接收集手机与插件恢复阶段。
  • 持续验证插件恢复：真实 npm 市场再次跑通坏插件崩溃、自动隔离、升级并重新启用和 Harness 重启；打包 Safe Mode 继续验证故障插件隔离与恢复横幅。

v0.1.2-rc.1.shell.9 （内核 0.1.2-rc.1）

  • 修复手机扫码后插件加载失败：随包 dsh-mobile-shell 升至 1.0.2。代理现在原样保留 Harness /plugins/??… 批量资源路径，不再把第二个问号 URL 编码后转发成 404；二维码、一次性配对码、设备会话与内核登录令牌仍保持分层隔离。
  • 补齐坏插件自动恢复闭环：插件导致启动失败时，桌面端继续自动隔离并重启；恢复后的正常主页现在会显示问题插件和「升级并重新启用」按钮。该按钮只允许当前已验证的 Harness 本机页面调用，并继续拒绝官方包和未列入恢复上下文的包。
  • 强化真实端到端门禁：新增从桌面二维码到手机浏览器、再到真实 Harness 输入控件的打包测试，分别覆盖 Android 风格 Chromium 与 iPhone 风格 WebKit；同时用真实 npm 插件执行「崩溃 → 自动隔离 → 页面升级 → 重新启用 → 重启成功」。
  • 修正发布故障注入的认证竞态：失败候选 shell.8 的 macOS 门禁在重试后用无令牌地址探测 Harness，偶发先于页面完成 cookie 交换而收到 401。shell.9 改为直接验证 supervisor 返回的带一次性启动令牌 URL，不放宽产品断言。

  • 修复手机扫码后插件加载失败：随包 dsh-mobile-shell 升至 1.0.2。代理现在原样保留 Harness /plugins/??… 批量资源路径，不再把第二个问号 URL 编码后转发成 404；二维码、一次性配对码、设备会话与内核登录令牌仍保持分层隔离。

v0.1.2-rc.1.shell.7 （内核 0.1.2-rc.1）

  • 桌面垃圾桶：删除的会话、预设和插件都先进垃圾桶，不再一去不返。在 Harness「设置 → 垃圾桶」中查看、按原位置还原（同名冲突自动落副本）、或彻底清除；保留 30 天，过期自动清理。
  • Agent 删除有兜底：Agent 执行的 rm 类删除命令会被桌面版拦截，目标先移入垃圾桶再放行；解析不了或越出工作区、触及 node_modules/.git 的可疑删除直接拦截并说明原因。可在「设置 → 桌面设置」关闭该开关。
  • 插件失败自动隔离：插件导致启动失败时，桌面版自动把问题插件移出启动列表并重启，应用先跑起来；被隔离的插件在恢复横幅中持续可见，升级即自动重新启用。
  • 边界说明：垃圾桶只覆盖桌面版自有资源与被拦截的 Agent 删除；壳外手动删除、系统其它操作不在覆盖范围。隔离与入桶都不删除原始文件，随时可逆。

v0.1.2-rc.1.shell.6 （内核 0.1.2-rc.1）

  • 修复扫码配对后手机提示需要重新认证：内核 0.1.2-alpha.2 起，dsh web 首页只在携带单次启动令牌或签名 cookie 时提供，配对成功后手机加载界面会收到内核的 401（"dsh web authentication required"）。桌面版现在把就绪 URL 中的启动令牌交给配对代理（dsh-mobile-shell 1.0.1），由代理换取签名会话 cookie 并附在转发请求上；内核重启时代理随之自动重启轮换令牌。手机端仍然只对桌面版代理认证，不接触内核令牌。
  • 修复 Windows 右上角按钮重叠：Windows/Linux 的原生最小化/最大化/关闭按钮区域会压住内核会话头部右上角的「Session log」导出按钮。桌面版在该两平台隐藏该胶囊按钮；同样的导出能力仍可通过 /export 斜杠命令使用。
  • 边界说明：代理只对上游出示自己换取的会话 cookie，不向手机下发内核令牌；隐藏按钮不减少任何功能入口。

v0.1.2-rc.1.shell.5 （内核 0.1.2-rc.1）

  • 发布链路自愈：release 或 GitCode 镜像任何一环失败都会自动开 issue（按标题去重，重复失败追加评论），不再出现“官网悄悄停在旧版本、没人知道”。Release 失败后官网数据同步也会照常兜底执行。
  • 一键提交问题：错误页新增「到 GitHub 提交问题」——自动预填版本、平台、内核、安全模式、疑似插件与失败原因，全部脱敏，不含日志原文或路径；诊断报告由你自己导出并拖进 issue，应用不会自动上传任何文件。
  • 升级结果语义修正：插件已是最新可获得版本时，错误页显示「已是当前可获得的最新版本,正在重启…」，不再让人误以为升级失败（registry 元数据可能滞后于刚发布的 dist-tag）。
  • 边界说明：支持入口只在壳自有错误页出现；预填内容不包含密钥、日志或用户路径。

更早版本的说明见 GitHub Releases。
