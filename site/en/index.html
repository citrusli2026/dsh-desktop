Send tasks to this computer from Feishu

Bundled cc-connect passes bot messages to local Harness in your chosen workspace. Keep this computer and Desktop running. The Feishu long connection needs neither a public IP nor LAN sharing.

1. Scan and save an application

Open Settings → Feishu connections, or Desktop tools → Connect → Feishu connections. Extensions → Manage Feishu connections and the existing Desktop settings entry remain available. Scan, wait until Desktop receives the credentials, then save a named application. Existing applications can be added manually.

2. Choose a workspace and open the connection

Save multiple applications, but connect one at a time. Configure model credentials in Harness first, then explicitly open cc-connect. Service started, Feishu online and task completed are distinct states.

3. Reduce noise or close the connection

Defaults are compact messages and a 3-second preview. Choose full/compact/quiet detail, classic/rich cards and progress styles. Close the connection, control auto-connect at startup or remove local settings in the same manager.

Closing the manager or minimizing does not disconnect; closing the main window exits and stops services. Safe Mode pauses the connection. macOS Secrets use mode-0600 plaintext files; legacy encrypted credentials need one re-entry. Windows policy is unchanged. Local removal does not delete the remote application; your organization controls permissions and publishing.

Current release: Harness 0.2.2-alpha.2, a kernel jump and an audited permission boundary

The bundled Harness moves to upstream 0.2.2-alpha.2, which resets the shell revision: the manifest pin and 32 kernel peers move together, release-age excludes are re-pinned, and the closure lockfile is regenerated and redeployed with closure satisfied. Both reviewed patches are rebuilt on the new bundles — the account popup fallback and onboarding guard are regenerated against the new source, and the session-trash lifecycle patch passes its upstream review (both edited bundles changed by ~5100 diff lines, every lifecycle anchor still resolves once, session creation moved into the new SessionCommandController, and the delegation now hangs off the byte-identical resolveAgent). Voice input works again: recording uses getUserMedia({ audio }), which the deny-by-default boundary rejected, so microphone audio is now granted while the camera, clipboard reads, notifications, fullscreen and display capture stay denied, and macOS carries the microphone usage string the OS requires before its per-app approval. Every desktop build must still render all 22 packaged extension surfaces on macOS, Windows and both Linux architectures before a release can publish; installation and desktop acceptance on real hardware or VMs remains a maintainer step.

Product boundary: the shell owns the desktop window, tray, runtime, supervision, recovery, updates, and local entry points. What you see and use is the official Harness WebUI — agents, sessions, tools, models, and plugin behavior all come from Harness itself.

What the desktop shell adds

  • Bundled runtime and one-click startup across Windows, macOS, and Linux.
  • Native window, tray entry, supervision, and recovery diagnostics.
  • Optional shortcut, launch-at-login, local notices, and a read-only health check in Settings → Desktop settings.
  • A manual-first community plugin market (the community dsh-market catalogue).
  • Isolated ~/.dsh-desktop data and a constrained renderer, so desktop permissions stay minimal.

RECOVERY AND CONTROL

Inspect, restore, or recover locally.

Desktop trash keeps supported deleted resources for 30 days, with restore and permanent-delete controls.

  • Recoverable: deleted sessions restore with one click in Settings → Trash.
  • Direct recovery: retry, Safe Mode, logs, and diagnostics stay close.
  • Explicit plugins: the installer contains no community plugins; every choice is manual.
