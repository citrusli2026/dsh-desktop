DSH Desktop Changelog

Versions are composite: <dsh kernel>.shell.<shell rev>. The kernel tracks the official @deepseek-ai/dsh package; shell revisions carry desktop-shell fixes and features only. Highlights below; full notes live on each GitHub release page.

v0.2.1-rc.2.shell.6 (kernel 0.2.1-rc.2)

  • Companion windows now work with real plugins: the HTML probe uses the main window's session instead of a credential-less Node fetch (which the Harness connection fence answers with 401), and a late showInactive() can no longer cover a main window the user already restored.
  • Click-through: a generic window.dshCompanion.setInteractive() lets a plugin page hand clicks on its transparent areas to the desktop; the window is interactive by default, so plugins that ignore it are unaffected.
  • Update prompt: macOS/Linux “new version available” opens the community download page in the user's locale instead of a GitHub release page.
  • Real-plugin release gate: opt-in pnpm run test:e2e:whale plus a HID click-through check; the fixture suite now covers the auth fence and the late-load race.
  • Boundary unchanged: no DOM access, no executeJavaScript, no approval bridge — approvals in the companion hand off to the main window.

v0.2.1-rc.2.shell.5 (kernel 0.2.1-rc.2)

  • Plugin companion windows (ADR 0043): an installed plugin can declare dsh.companion { route, width, height, title, showOnMinimize } in its own package.json; the shell discovers it read-only, probes the route for a 2xx HTML response, and hosts it in a sandboxed window that appears when the main window is minimized and hides when it is restored.
  • Security boundary: sandboxed with context isolation, no Node integration, window.open denied, navigation pinned to the declared path; the preload only exposes hide/focus-main. No DOM access, no executeJavaScript, no approval bridge — approvals stay in the main window.
  • Panel entry: a new “Companion windows” group in the desktop-tools panel toggles declared companions; placement follows the display containing the main window and windows are destroyed on quit.
  • Community request #130: the whale widget only needs the declaration and its /dsh-whale/pet route — no app.asar patching and no disabling auto-update.

v0.2.1-rc.2.shell.4 (kernel 0.2.1-rc.2)

  • The desktop-tools panel now closes on an outside pointerdown; the trigger toggle and drag behaviour are unchanged (#123).
  • Every panel action reports failures — non-true results and thrown errors — in a single alert status line (#125).
  • The Feishu manager refuses an empty workspace before IPC, with a field-level error, aria-invalid and focus; the settings form mirrors the same error (#124).
  • The native workspace picker returns a discriminated result: cancel stays silent, an unusable directory is explained (#126).
  • Menu/tray failures raise a native notification plus a log line instead of dying in the console (#127).
  • ADR 0042 records the per-surface failure contract (#128).

v0.2.1-rc.2.shell.3 (kernel 0.2.1-rc.2)

  • Electron runtime upgraded to 44.9.1: the main process now runs Chromium 152.0.7977.167 / Node 24.22.0 (the same Node 24 line as the bundled Harness at 24.21.0), taking upstream security and stability fixes. Shell features, UI and data directory are unchanged, so the installer upgrades in place.
  • Test toolchain moved to Playwright 1.64.1: end-to-end and packaged regression stay on the current driver; this build still passes the 24 packaged cases and the four-runner visual gate.
  • Boundary note: the kernel stays 0.2.1-rc.2 and the signing/notarization boundary is unchanged; the desktop-tools panel's star entry only opens the repository page with ?ref=app-panel attribution and sends no telemetry.

v0.2.1-rc.2.shell.2 (kernel 0.2.1-rc.2)

  • The panel's INFO group is now part of the four-runner visual gate: the desktop-tools panel's INFO group (About + Star on GitHub) is screenshotted and asserted on macOS, Windows, Linux x64 and Linux arm64, and the surface contract grows from 21 to 22 — a platform that fails to render it fails the build, so the panel's only persistent product entry can no longer regress silently.
  • No behaviour change: the kernel stays 0.2.1-rc.2 and only the shell revision advances; the Star entry has shipped since .shell.1, this build adds no feature and behaves exactly like the previous one.
  • Boundary note: the star entry only opens the repository page with ?ref=app-panel attribution and sends no telemetry; the signing/notarization boundary is unchanged.

v0.2.1-rc.2.shell.1 (kernel 0.2.1-rc.2)

  • Star entry in the desktop tools panel: the INFO group gains a "Star on GitHub" row that opens the repository in the default browser with ?ref=app-panel attribution, so panel clicks can be told apart from website ones. It is a persistent link only — no popup, no nagging, and it leaves the rest of the panel untouched.
  • The website shipped its own fact-check iteration alongside: corrected claims (the bundled runtime is Node.js 24, not 22; the retired npx validation command is gone; the unverified plugin count is removed; CI gate wording no longer says "real machine"), the two independent copy sources were reconciled (data-i18n now actually applies), changelog entries were matched bullet for bullet across languages, and SEO gained structured data, a crawlable release snapshot, git-derived sitemap dates and a bilingual 404. All of it deploys with the site, no new installer required.
  • Boundary note: both star entries only open the repository page and send no telemetry; the kernel stays at 0.2.1-rc.2 and the signing/notarization boundary is identical to the previous build.

v0.2.1-rc.2.shell.0 (kernel 0.2.1-rc.2)

  • Kernel upgrade 0.2.1-rc.1 → 0.2.1-rc.2: 32 @deepseek-ai/dsh-* peers re-synced, the manifest lockfile regenerated, release-age exemptions re-pinned (315 → 302 entries, 13 kept at the version resolved in the lockfile). Both reviewed shell patches are confirmed for the new kernel: the two patched upstream bundles are byte-identical between the kernels and the transforms still match, so the patch manifest now records the reviewed-kernel list explicitly.
  • macOS control-socket fix: the sidecar's per-application data directory pushed run/api.sock past the sun_path limit, so the manager reported a working connection as closed. The sidecar now gets a short $TMPDIR alias (a symlink to the real directory, no data migration): the 116-character path fails to bind where the 93-character alias succeeds, and a packaged run logs api server started socket=/var/folders/….
  • Rich Feishu cards by default for new connections (card style rich, progress display card); existing configurations and explicit legacy choices are untouched.
  • Linux arm64 packages: ubuntu-24.04-arm joined the release matrix and builds -arm64.deb from the same sources as amd64 (ten files in the GitHub Release, eight of them user-visible installers and checksums), and the in-app repair link follows the architecture it runs on.
  • Four-runner visual gate in the release flow: the macOS, Windows, Linux x64 and Linux arm64 runners must each render all 21 packaged extension surfaces (first-run and safe mode, the floating Feishu quick control, five Feishu manager states, six settings panes, LAN pairing, trash, recovery and loading) before a release publishes, and the screenshots ship as artifacts. Installation and desktop acceptance on real hardware or a VM stays a maintainer step (scripts/verify-visual-evidence.mjs).
  • Boundary note: all verification ran in isolated local or CI environments; health-check results are rendered locally in sanitized form and are never uploaded automatically.

v0.2.1-rc.1.shell.1 (kernel 0.2.1-rc.1)

  • Plugin crashes now self-heal (#115 family): a loader row that imports a package the bundled kernel does not carry used to leave only "startup failed" and a restart loop — Safe Mode could not help because it only collected rows inserted by user bundles, while the failing row usually comes from cordis.patch.yml or a file it includes. This release classifies that failure as missing-package, points the error page at the fix (update the app or disable the plugin), extends Safe Mode over the profile/home patch layers and their includes (user overrides of *official* rows stay enabled), and records non-bundle failing rows in a shell-owned quarantine overlay that skips them on the next start — reversible from the error page, the extensions menu, or by updating or disabling the plugin.
  • An unwritable profile no longer loops (#100/#116): the kernel rewrites profiles/web/cordis.yml on every start, so a read-only file (or an ACL/Controlled Folder Access block) used to look like "blank screen, then it never starts again" while the health check still reported the data folder as writable. The shell now probes the profile *files* before spawning, refuses to spin on a doomed boot, and shows a page with the concrete path and a one-click "repair file permissions and restart" action; the storage health check uses the same probe and the diagnostic report gained a profile_write= line.
  • Blank renderers are diagnosable (#100): renderer console errors/warnings and unresponsive events are captured into a bounded, redacted renderer_errors section of the diagnostic report, and the renderer-failure page now carries the first exception.
  • More complete diagnostics: the plugin inventory reports patch_layers and unkeyed_rows.
  • The bundled kernel is unchanged at @deepseek-ai/dsh 0.2.1-rc.1; only the shell revision moves, so upstream 0.2.1-rc.2 is deliberately not pulled in by a shell release.
  • Everything stays local-first: the diagnostic report is still generated on-device and never uploaded automatically, and the repair only clears the read-only attribute — it does not touch ACLs, security-software settings, or user data.
