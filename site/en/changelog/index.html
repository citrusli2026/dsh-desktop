DSH Desktop Changelog

Versions are composite: <dsh kernel>.shell.<shell rev>. The kernel tracks the official @deepseek-ai/dsh package; shell revisions carry desktop-shell fixes and features only. Highlights below; full notes live on each GitHub release page.

v0.1.7-rc.1.shell.1 （kernel 0.1.7-rc.1）

  • Fix desktop native-surface language fallback after Harness 0.1.7 migrates legacy settings by reading locale and theme preferences from the active web profile and following profile edits.
  • Keep compatibility with existing and archived settings files without recreating the legacy file after migration. Preferences stay in the local Harness profile.

v0.1.7-rc.1.shell.0 （kernel 0.1.7-rc.1）

  • Kernel bump: bundled @deepseek-ai/dsh locked to 0.1.7-rc.1 (previous 0.1.6-alpha.2, jumping straight to the rc line); shell revision reset to 0. See the official upstream release notes for kernel changes.
  • Kernel 0.1.7 behavior changes: a broken community plugin is now isolated instead of crashing the boot; settings migrate losslessly (old file archived byte-exact as .imported); the settings entry moved into the account popup. The shell's startup smoke, upgrade-retention assertions and settings-navigation E2E follow the new contract (landed with v0.1.6-alpha.2.shell.4, first exercised on a kernel release here).
  • New-kernel peer gaps (dsh-client-store, dsh-deepseek-account) joined the closure; sub-packages without an rc.1 release stay at their resolved versions. Zero known vulnerabilities in both npm trees.
  • Desktop shell unchanged. If a community plugin is incompatible with the new kernel, the error page offers one-click Update / Disable recovery.
  • Known behavior change: after the kernel's lossless settings.yaml migration (archived as .imported), the shell's native surfaces (menu/tray/notifications) follow the OS language; the in-app language choice no longer survives a restart until the shell reads the kernel's new settings store (#68).

  • Kernel bump: bundled @deepseek-ai/dsh locked to 0.1.7-alpha.2 (previous 0.1.6-alpha.2); shell revision reset to 0. See the official upstream release notes for kernel changes.
  • Kernel 0.1.7 behavior changes: a broken community plugin is now isolated instead of crashing the boot; settings migrate losslessly (old file archived byte-exact as .imported); the settings entry moved into the account popup. The shell's startup smoke, upgrade-retention assertions and settings-navigation E2E follow the new contract (landed with v0.1.6-alpha.2.shell.4, first exercised on a kernel release here).
  • New-kernel peer gaps (dsh-client-store, dsh-deepseek-account) joined the closure; 12 sub-packages without a 0.1.7-alpha.2 release stay at their resolved versions. Zero known vulnerabilities in both npm trees.
  • Desktop shell unchanged. If a community plugin is incompatible with the new kernel, the error page offers one-click Update / Disable recovery.
  • Known behavior change: after the kernel's lossless settings.yaml migration (archived as .imported), the shell's native surfaces (menu/tray/notifications) follow the OS language; the in-app language choice no longer survives a restart until the shell reads the kernel's new settings store (#68).

v0.1.7-alpha.1.shell.0 （kernel 0.1.7-alpha.1）

  • Kernel bump: bundled @deepseek-ai/dsh locked to 0.1.7-alpha.1 (previous 0.1.6-alpha.2); shell revision reset to 0. See the official upstream release notes for kernel changes.
  • New-kernel peer gaps (dsh-client-store, dsh-deepseek-account) joined the closure; 12 sub-packages without a 0.1.7-alpha.1 release stay at their resolved versions. Kernel 0.1.7 now isolates a broken community plugin and keeps booting — the shell startup smoke follows that contract. Zero known vulnerabilities in both npm trees.
  • Desktop shell unchanged. If a community plugin is incompatible with the new kernel, the error page offers one-click Update / Disable recovery.

v0.1.6-alpha.2.shell.4 （kernel 0.1.6-alpha.2）

  • LAN mobile access now supports VPN virtual adapters (#63): CGNAT 100.64.0.0/10 addresses (Tailscale/ZeroTier) are accepted as private LAN IPs. Auto-discovery keeps physical NICs first and falls back to VPN adapters; a phone on the same virtual network can pair via the QR code. DSH_LAN_IP also accepts CGNAT addresses.
  • Packaging E2E hardened across kernel UI versions; the upgrade smoke follows kernel 0.1.7's settings-file migration contract ahead of the next kernel bump. Bundled kernel unchanged at 0.1.6-alpha.2.

v0.1.6-alpha.2.shell.3 （kernel 0.1.6-alpha.2）

  • Windows-first iteration: the shell now proactively detects a missing Microsoft VC++ 2015-2022 redistributable (the dependency behind issue #56's ERR_DLOPEN_FAILED failures), shows a one-time first-run dialog linking the official installer, and reports a dedicated "Windows runtime library" item in the health check.
  • dlopen failures are classified separately on error pages and in exported diagnostics — users see "missing VC++ runtime or antivirus quarantine" with concrete steps instead of a raw log.
  • The Windows installer UI now follows the system language (Chinese/English). Bundled kernel unchanged at 0.1.6-alpha.2; all detection is local, nothing is uploaded.

v0.1.6-alpha.2.shell.2 （kernel 0.1.6-alpha.2）

  • New release gate: every Windows installer is unpacked and verified before publish — bundled node.exe, the sharp native chain (.node + libvips DLLs), the closure integrity manifest, mobile-shell, and agent-trash-hook must be present, with the highest-risk binaries hashed against the packaged closure manifest. Moves #39/#56-class verification from "discovered on user machines" to "blocked in the release pipeline".
  • The verification method is packaged as scripts/verify-windows-installer.mjs (runnable locally with 7-Zip). Bundled kernel unchanged at 0.1.6-alpha.2.

v0.1.6-alpha.2.shell.1 （kernel 0.1.6-alpha.2）

  • The trash settings section is rewritten on the shared settings design system: group cards, real tabs, kind badges, retention countdown, guided empty states.
  • Irreversible actions (delete-forever, clear-expired) now require an inline two-step confirm; the sessions tab tells the truth — delete moves a session to the trash (recoverable for 30 days) instead of claiming to destroy it.
  • Fixed archived-session detection (the kernel nests the archived list under global; the shell now reads both shapes and preserves the unit header on write) and kernel overlays now retire to the trash when you restore the bundled kernel.
  • New packaged E2E drives the full UI journey (restore, boot-time expiry sweep, confirmed purge, session-to-trash) plus contract assertions guarding the design system.
