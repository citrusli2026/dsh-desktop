DSH Desktop Changelog

Versions are composite: <dsh kernel>.shell.<shell rev>. The kernel tracks the official @deepseek-ai/dsh package; shell revisions carry desktop-shell fixes and features only. Highlights below; full notes live on each GitHub release page.

v0.1.2-rc.1.shell.2 （2026-09-04, kernel 0.1.2-rc.1）

  • New dismissible four-step first-success guide (runtime → workspace → model → first task); "Extension entry / settings" renamed to "Desktop tools / Desktop settings".
  • One-click health check: bundled runtime, data folders, loopback, profile, plugins, versions — local and read-only by default.
  • Windows upgrade cleanup tolerates transient file locks.

v0.1.2-rc.1.shell.0 （2026-09-04, kernel bump）

  • Kernel locked to official @deepseek-ai/dsh 0.1.2-rc.1: session loading, long-session memory and dense realtime rendering improvements.
  • Pinned safe versions of fast-uri, qs and @xmldom/xmldom; zero known vulnerabilities in both lockfiles.

v0.1.2-alpha.4.shell.3 （2026-09-02）

  • Plugin install feedback: staged progress for dsh-market (prepare, download, verify, restart), sanitized retryable failure causes.
  • Cross-version upgrade verification: all three platforms really upgrade the previous public release; user profile contents preserved item by item.
  • Windows upgrades now silently uninstall the old build and install in place instead of NSIS overwriting.

v0.1.2-alpha.3.shell.0 （2026-09-01）

  • Extension overlay reorganized around "connect → recover → info"; pairing a mobile device is the primary action.
  • Settings sections regrouped; fixed narrow-window layout issues across LAN, shortcut, market and Safe Mode cards.

v0.1.2-alpha.2.shell.0 （2026-08-31）

  • Settings condensed: Safe Mode promoted to the first screen; low-frequency tools moved under "More shell tools".
  • Website carousel now uses real app screenshots matched per language and theme.

v0.1.1-rc.2.shell.15 （2026-08-30）

  • Startup state feedback: starting / waiting / retrying / running / recovery paused, with attempt counts.
  • Tray, settings, loading page and diagnostic reports share one lifecycle state model.
