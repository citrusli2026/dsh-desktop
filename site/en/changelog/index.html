DSH Desktop Changelog

Versions are composite: <dsh kernel>.shell.<shell rev>. The kernel tracks the official @deepseek-ai/dsh package; shell revisions carry desktop-shell fixes and features only. Highlights below; full notes live on each GitHub release page.

v0.2.1-alpha.1.shell.2 （kernel 0.2.1-alpha.1）

  • Upgrade the bundled kernel from 0.2.0-rc.2 to 0.2.1-alpha.1 and sync the packaged dependency closure.
  • Persist the chosen LAN address and validate pairing URLs on multi-interface hosts.
  • Match the trash page to the settings design, localize Chinese dates, and report active-session deletion failures accurately.
  • Clean up the dsh-desktop process family between Windows NSIS residue scenarios so the next installer cannot block on an interactive close prompt.
  • No new permissions or user-data changes. The release includes the downstream http-cache-semantics security patch and passed both dependency audits.

v0.2.1-alpha.1.shell.1 （kernel 0.2.1-alpha.1）

  • Upgrade the bundled kernel from 0.2.0-rc.2 to 0.2.1-alpha.1 and sync the packaged dependency closure.
  • Persist the chosen LAN address and validate pairing URLs on multi-interface hosts.
  • Match the trash page to the settings design, localize Chinese dates, and report active-session deletion failures accurately.
  • Clean up a silently launched desktop process between Windows NSIS residue scenarios so the next installer cannot block on an interactive close prompt.
  • No new permissions or user-data changes. The release includes the downstream http-cache-semantics security patch and passed both dependency audits.

v0.2.1-alpha.1.shell.0 （kernel 0.2.1-alpha.1）

  • Upgrade the bundled kernel from 0.2.0-rc.2 to 0.2.1-alpha.1 and sync the packaged dependency closure.
  • Persist the chosen LAN address and validate pairing URLs on multi-interface hosts.
  • Match the trash page to the settings design, localize Chinese dates, and report active-session deletion failures accurately.
  • No new permissions or user-data changes. The release includes the downstream security patch for http-cache-semantics and passed both dependency audits.

v0.2.0-rc.2.shell.0 （kernel 0.2.0-rc.2）

  • Upgrade the bundled kernel from 0.2.0-rc.1 to 0.2.0-rc.2 and sync the 34 dsh package pins and resolved closure.
  • Keep the sign-in authorization URL opening once per attempt in the system browser, with the current theme, rebuilt and verified against rc.2.
  • Enforce plugin peer compatibility during install; a compatible community market release is selected automatically after it clears the bundled pnpm publish-age window.
  • No new permissions or data-directory changes. Windows x64, macOS arm64, and Linux packages are built by the release pipeline.

v0.2.0-rc.1.shell.0 （kernel 0.2.0-rc.1）

  • Kernel upgrade 0.1.7-rc.2 → 0.2.0-rc.1 (first 0.2.0 release candidate); 34 dsh-* peer pins synced, release-age excludes re-pinned (229), and the sign-in auto-open patch rebuilt against the new version.
  • Kernel-side plugin installs now enforce peer compatibility: mismatched plugin versions are rejected with an explanation and an explicit risk-exemption path instead of crashing later. The community market (dshmarket) needs 1.66.4+ for this kernel; the bundled installer resolves to it automatically once published for 24 hours.
  • Upgrade-path and broken-plugin isolation contracts re-verified on the new kernel; LAN pairing E2E and packaged smokes green.

v0.1.7-rc.2.shell.2 （kernel 0.1.7-rc.2）

  • #65 fully supported: LAN pairing now listens on every private address (physical NICs + VPN virtual adapters) with one QR code per address, labelled lan/vpn.
  • NIC checkbox selection (persisted) and DSH_LAN_IP override (single / comma list / 0.0.0.0) in the pairing panel.
  • Proxy fix: the multi-address rewrite left a nested loop so the WS-upgrade handler and SSE timeout config never reached the listening servers; repaired and smoke/E2E verified.

v0.1.7-rc.2.shell.1 （kernel 0.1.7-rc.2）

  • Critical macOS launch fix (#79): v0.1.7-rc.2.shell.0 shipped the closure manifest after the ad-hoc seal, so macOS reported the app as damaged. macOS builds no longer ship a manifest — integrity on macOS is now enforced by the code signature itself, verified at runtime via codesign --verify --deep --strict in the health check. macOS shell.0 users must update.
  • The bottom-left account-popover login flow (popover → Sign in → authorize URL) is covered end-to-end by packaged E2E, including the rc.2-rebuilt auto-open patch.
  • The LAN pairing window now renders one QR code per reachable address, labeled LAN vs VPN virtual adapter (#65 follow-up). Bundled kernel unchanged at 0.1.7-rc.2.

v0.1.7-rc.2.shell.0 （kernel 0.1.7-rc.2）

  • Kernel bump to official @deepseek-ai/dsh 0.1.7-rc.2 (previous 0.1.6-alpha.2 line via rc.1).
  • UOS/Deepin desktop adaptation (#73): the Linux main window now carries the app icon (_NET_WM_ICON) so taskbars stop showing a default icon, and Linux restores the full native title bar — the 0.1.7 web UI's top-right actions no longer collide with native window controls. macOS/Windows keep their hidden-title-bar styles.
  • The DeepSeek login auto-open patch was rebuilt against rc.2. Closure peers synced; zero known vulnerabilities.
