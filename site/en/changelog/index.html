DSH Desktop Changelog

Versions are composite: <dsh kernel>.shell.<shell rev>. The kernel tracks the official @deepseek-ai/dsh package; shell revisions carry desktop-shell fixes and features only. Highlights below; full notes live on each GitHub release page.

v0.1.2-rc.1.shell.4 （kernel 0.1.2-rc.1）

  • Fixed real-world failure signatures: the detector now matches the failed to import loader entry variant (the one actual kernel-API cliffs emit) and the missing-bundle cannot resolve profile bundle error, so the error page finally lists suspects in real crashes; a failed first boot now carries the harness's own output tail instead of a one-line summary.
  • Kernel-cliff classification: the error page explains the missing-export cause and points at one-click Update; diagnostics reports failure_cause.
  • New packaged E2E proves the full recovery loop against the real registry (damaged plugin → error page Update → real install → harness boots).
  • Release automation: merging a dsh-bump PR now writes release notes, tags, and triggers the full gated pipeline, then dispatches the GitCode mirror; the site changelog is generated from release notes.

v0.1.2-rc.1.shell.3 （kernel 0.1.2-rc.1）

  • Error-page plugin recovery: when startup fails on incompatible community plugins, the recovery center lists each suspect with Update, Disable, and Update-all-and-restart actions; updates pull the latest npm version via the existing dsh plugin add path, disable only removes the boot bundle entry (files kept, reversible from Settings → Plugins), and official bundles are always refused.
  • New E2E coverage: a simulated plugin crash renders the recovery rows, disabling boots the app again with the manifest verified on disk; the LAN pairing QR window is covered end to end (private address, single-use 6-digit code, QR rendered).
  • Bundled kernel unchanged at @deepseek-ai/dsh 0.1.2-rc.1 (shell revision +3).

v0.1.2-rc.1.shell.2 （kernel 0.1.2-rc.1）

  • Renamed the hidden “Extensions” entry to Desktop tools / Desktop settings and added a dismissible, non-modal runtime → workspace → model → first-task guide that retires itself after the first successful task.
  • Added a one-click health check for bundled files and versions, both data roots and disk space, Harness loopback, profile, plugins, market, Safe Mode, and kernel state, with clear OK / warning / failed actions.
  • Local checks are read-only and offline by default. Proxy, registry, and update-source probes require explicit opt-in; results are sanitized, never uploaded, and never repair user files automatically.
  • The plugin market remains optional and manually installed; no community plugin is bundled or restored silently.
  • Windows cross-version CI now tolerates transient installer file locks during temporary cleanup instead of misclassifying a successful upgrade as a product failure.

v0.1.2-rc.1.shell.0 （kernel 0.1.2-rc.1）

  • Upgraded and pinned the bundled kernel to official @deepseek-ai/dsh 0.1.2-rc.1, including upstream long-session, connection recovery, model configuration, and UI improvements.
  • Fixed the daily kernel watcher by packaging the pinned mobile-shell Web artifact before smoke validation, and removed speculative root-cause language from future failure issues.
  • Raised vulnerable transitive dependencies to explicit security floors; both the root tree and production Harness closure pass the official npm advisory audit with no known vulnerabilities.
  • Local gates cover 193 unit tests, Electron E2E, real Harness rendering, real/offline dsh-market paths, Safe Mode recovery, and a macOS upgrade that preserves seven user-owned files. Community plugins remain explicit opt-in installs.

v0.1.2-alpha.4.shell.3 （kernel 0.1.2-alpha.4）

  • Manual dsh-market installation reports prepare, download, verification, and restart phases, preserves the result across the Harness reload, and shows the actual installed profile version.
  • Actionable failure categories and sanitized diagnostics keep failed installs explainable and retryable. Packaged E2E covers deterministic offline failure and a real install under Chinese/dark/minimum-width and Unicode-path conditions; its log uses the host OS temporary directory.
  • Every release platform verifies the previous installer checksum and preserves user-owned Harness and shell state across an upgrade. macOS/Linux use in-place replacement; Windows silently removes old application binaries before installing the new version to the same target because electron-builder's assisted NSIS silent-overwrite path can stall.
  • Clean CI runs skip dedicated market specs before fixture setup, while their packaged gates still run separately. Bundled/CI pnpm is patched to 11.11.0.
