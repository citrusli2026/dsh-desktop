# dsh-desktop v0.2.2-alpha.2.shell.0

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` 0.2.2-alpha.2（由 0.2.1-rc.2 升级，壳修订归零）。

## 本次更新

- **内核升级 0.2.1-rc.2 → 0.2.2-alpha.2**（复合版本规则：内核升级把壳修订归零）：manifest pin 与
  32 个 `dsh-*` peer 一起更新，`cordis-plugin-group` 1.0.5-alpha.1 → 1.0.6-alpha.1 以满足新内核
  app-boot 的 peer；release-age 豁免按 315 → 302 条重钉，闭包锁文件重生成后重新部署，peer 审计
  `closure satisfied`。两处维护补丁都在新内核上重新落地：账号设置的弹窗回退与 onboarding 守卫
  按新版源码重新生成（仍为原来的两处 hunk）；会话垃圾桶的生命周期补丁完成上游复审（两个被改
  bundle 的上游 diff 共约 5100 行，所有锚点仍唯一命中；会话创建拆到了新的
  `SessionCommandController`，旧锚点用的外层 `inspect` 被上游删除，委托改为挂在字节相同的
  `resolveAgent` 前向方法上），并登记进 `REVIEWED_KERNELS`。
- **修复语音输入无法录音**（ADR 0050）：Harness 的语音输入用 `getUserMedia({ audio })` 录提示词，
  而默认拒绝的权限边界把它按 `media` 拒了，已发布的麦克风按钮只会报 `RecordingError("permission")`。
  现在 `media` 只在请求类型**全部是音频**时放行——摄像头（`video`）、音视频混合、空列表与未知
  类型继续拒绝；macOS 的 `Info.plist` 增加 `NSMicrophoneUsageDescription`（缺少它系统会直接终止
  进程），首次录音仍由 macOS 逐应用授权。
- **权限边界逐项复审**（ADR 0050 记录了检索范围与结论）：把内置闭包里所有需要权限的 Web API 过了
  一遍——只有剪贴板写入（0049）与麦克风两项被已发布界面使用；`clipboard-read` 的两个调用点分别是
  xterm 的能力探测和电子表格预览里带内部剪贴板回退的显式「粘贴」，继续拒绝；通知、全屏、指针锁、
  屏幕捕获、定位、分享、文件选择器、`storage.persist`、`SpeechRecognition`、`window.print` 在已发布
  界面中均无调用，继续拒绝。

## English Summary

- **Kernel 0.2.1-rc.2 → 0.2.2-alpha.2** (a kernel bump resets the shell revision to 0): the manifest
  pin moved with 32 `dsh-*` peers, `cordis-plugin-group` went 1.0.5-alpha.1 → 1.0.6-alpha.1 to satisfy
  the new app-boot peer, the release-age excludes were re-pinned (315 → 302 entries), the closure
  lockfile was regenerated and redeployed, and the peer audit reports `closure satisfied`. Both
  maintenance patches were rebuilt on the new bundles: the account settings popup fallback and
  onboarding guard were regenerated against the new source (same two hunks), and the session-trash
  lifecycle patch passed its upstream review — the two edited bundles changed by ~5100 diff lines, all
  lifecycle anchors still resolve once, session creation moved into the new
  `SessionCommandController`, and the outer `inspect` the delegation anchored on was removed, so the
  delegation now hangs off the byte-identical `resolveAgent` forwarder; the kernel is recorded in
  `REVIEWED_KERNELS`.
- **Voice input can record again** (ADR 0050): the Harness voice input records the prompt with
  `getUserMedia({ audio })`, which the deny-by-default boundary rejected as `media`, so the shipped
  microphone button only ever reported `RecordingError("permission")`. `media` is now granted only
  when every requested type is audio — camera video, audio+video, empty lists and unknown types stay
  denied — and `NSMicrophoneUsageDescription` is added to the macOS `Info.plist` (without it the OS
  terminates the process); the first recording still needs the per-app system approval.
- **The rest of the boundary was audited** (ADR 0050 records the scope and verdicts): every
  permission-gated web API in the bundled closure was checked and only clipboard write (0049) and the
  microphone are used by shipped surfaces; `clipboard-read` stays denied because its two call sites
  are xterm's capability probe and the spreadsheet preview's explicit paste menu, which already falls
  back to its own buffer; notifications, fullscreen, pointer lock, display capture, geolocation,
  share, file pickers, `storage.persist`, `SpeechRecognition` and `window.print` are unused and stay
  denied.
