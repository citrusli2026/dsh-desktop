# dsh-desktop v0.2.1-rc.2.shell.6

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` 0.2.1-rc.2（未变，壳修订 5 → 6）。

## 本次更新

- **插件伴随窗口可用性修复**：真实插件（例如小鲸鱼 `/dsh-whale/pet`）的路由通常经过 Harness 的连接
  鉴权栅栏，旧探针用无凭据的 Node `fetch` 会被 401，导致伴窗永远打不开；现在探针改用主窗口的 session，
  看到的结果与伴窗一致。同时修掉「加载慢时晚到的 `showInactive()` 把已恢复的主窗口重新盖住」的竞态。
- **透明区域点击穿透**：伴窗新增通用 `window.dshCompanion.setInteractive()`，插件页面可以自己判断指针
  是否在自己的 UI 上，让空白区域把点击交给桌面，不再整块挡住 560×620 的范围。窗口默认仍可交互，不实现
  这一步的插件行为不变。
- **升级弹框改跳社区官网**：macOS / Linux 的「发现新版本」不再打开 GitHub Release，改为按语言打开社区
  下载页（`dsh-desktop.com/download` / `/en/download`），按钮文案改为「打开下载页」。
- **真实插件回归门禁**：新增 opt-in 的 `pnpm run test:e2e:whale`（发现插件 → 最小化开窗 → 审批
  fail-closed 唤回主窗口 → 面板重开 → `−` 恢复），以及 `scripts/whale-clickthrough.mjs`（真实鼠标事件
  验证穿透）。默认 fixture 用例同时补上鉴权栅栏与慢加载竞态。
- **边界说明**：通用壳仍然不读 Harness DOM、不调用 `executeJavaScript`、不提供审批桥；桌宠里的审批动作
  只会把用户带回主窗口确认，不会在伴窗内伪造批准结果。所有判断都在本机完成，不新增联网行为。

## English Summary

- **Companion windows now work with real plugins**: the HTML probe uses the main
  window's session instead of a credential-less Node `fetch` (which the Harness
  connection fence answers with 401), and a late `showInactive()` can no longer
  cover a main window the user already restored.
- **Click-through**: a generic `window.dshCompanion.setInteractive()` lets a
  plugin page hand clicks on its transparent areas to the desktop; the window is
  interactive by default, so plugins that ignore it are unaffected.
- **Update prompt**: macOS/Linux “new version available” opens the community
  download page in the user's locale instead of a GitHub release page.
- **Real-plugin release gate**: opt-in `pnpm run test:e2e:whale` plus a HID
  click-through check; the fixture suite now covers the auth fence and the
  late-load race.
- **Boundary unchanged**: no DOM access, no `executeJavaScript`, no approval
  bridge — approvals in the companion hand off to the main window.
