# dsh-desktop v0.1.6-alpha.2.shell.3

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` 0.1.6-alpha.2（未变，壳修订 +3）。

本轮为 **Windows 体验专项**（Windows 下载占全平台 75%）：把 #56 暴露的"原生组件加载失败"从被动报错变成主动检测与精确指引。

## 本次更新

- **VC++ 运行库主动检测**：Windows 首次启动时检测 Microsoft VC++ 2015-2022 运行库（sharp 等原生组件的依赖），缺失时弹出一次性提示，一键打开微软官方下载页；选择"稍后再说"后本次安装不再打扰。「运行体检」同步新增 **Windows 运行库** 项，随时可查。
- **加载失败精确归因**：安装或启动报 `ERR_DLOPEN_FAILED` 时，错误页与导出的诊断报告不再只有原始日志——现在明确指出"缺少 VC++ 运行库或杀毒软件隔离了文件"，并给出官方运行库直链与杀软白名单指引。
- **安装器中英双语**：Windows 安装界面按系统语言自动显示中文或英文（此前默认英文）。
- **内核与边界不变**：内置内核仍为 0.1.6-alpha.2；不新增权限、不改变插件安装与数据目录边界；检测全部在本机完成，不上传任何信息。

## English Summary

- Windows-first iteration: the shell now proactively detects a missing Microsoft VC++ 2015-2022 redistributable (the dependency behind issue #56's ERR_DLOPEN_FAILED failures), shows a one-time first-run dialog linking the official installer, and reports a dedicated "Windows runtime library" item in the health check.
- dlopen failures are classified separately on error pages and in exported diagnostics — users see "missing VC++ runtime or antivirus quarantine" with concrete steps instead of a raw log.
- The Windows installer UI now follows the system language (Chinese/English). Bundled kernel unchanged at 0.1.6-alpha.2; all detection is local, nothing is uploaded.
