# dsh-desktop v0.2.1-rc.2.shell.11

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` 0.2.1-rc.2（未变，壳修订 10 → 11）。

## 本次更新

- **修复聊天页代码框「复制」按钮点击没有任何反应**（#134）：消息行的复制、代码框右上角的复制、
  路径/JSON 复制全部失效。原因是 ADR 0014 的「渲染层权限默认拒绝」把 Chromium 写入前检查的
  `clipboard-sanitized-write` 也一起拒了，`navigator.clipboard.writeText` 直接抛
  `NotAllowedError: Write permission denied`；上游客户端只在异步 API **不存在**时才回退
  `execCommand('copy')`，于是失败完全静默（不写剪贴板、图标不变、也没有报错）。按 ADR 0049
  改为窄白名单：只放行 `clipboard-sanitized-write`，`clipboard-read`、`media`、`geolocation`、
  `notifications`、`display-capture`、`openExternal` 等继续拒绝。
- **修复主分支 CI 每天变红**（`test/site-generators.test.ts`）：下载快照的断言原来无条件要求
  「GitCode」字样，但它取决于实时站数据——`site-refresh` 机器人会在镜像完成前写入
  `gitcode_ok=false`，于是每个这样的数据态都把 CI 打红。改为按数据断言（镜像成功的安装包才要求
  徽标），并用 fixture 覆盖「有镜像 / 无镜像」两种渲染结果。
- **修复 dsh-watch 每日失败**：`scripts/version.mjs` 静态 import 了依赖 `yaml` 的
  `kernel-patches.mjs`，而工作流在 `pnpm install` **之前**就运行 `version.mjs check`（裸检出），
  于是每天以 `ERR_MODULE_NOT_FOUND` 退出，被判成「registry outage」，上游 `0.2.2-alpha.2` 因此
  没被报出来。改为在 `bump dsh` 路径内惰性加载，新增裸检出回归测试，工作流里也写明了这条约束。
- **issue / PR 状态**：发布前 0 个 open issue、0 个 open PR（shell.8 的失败自动单 #133 与已被
  通用伴窗取代的 PR #131 已在 shell.10 关闭）。

## English Summary

- **Fix the chat copy buttons** (#134): the message-row copy, the code-block header copy and every
  path/JSON copy silently did nothing. ADR 0014's deny-by-default renderer boundary also denied
  `clipboard-sanitized-write`, so `navigator.clipboard.writeText` rejected with
  `NotAllowedError: Write permission denied`, and the client only falls back to `execCommand('copy')`
  when the async API is missing. ADR 0049 adds a narrow allowlist: `clipboard-sanitized-write` only;
  `clipboard-read`, `media`, `geolocation`, `notifications`, `display-capture` and `openExternal` stay
  denied.
- **Fix the daily main-branch CI failure** (`test/site-generators.test.ts`): the download snapshot
  assertion demanded a “GitCode” badge unconditionally, but the site-refresh bot records
  `gitcode_ok=false` until the mirror finishes, so any such data state turned CI red. It now asserts
  from the data and covers both badge states with a fixture.
- **Fix the failing dsh-watch run**: `scripts/version.mjs` statically imported `kernel-patches.mjs`
  (which needs `yaml`) while the workflow runs `version.mjs check` on a bare checkout before
  `pnpm install`, so every daily run died with `ERR_MODULE_NOT_FOUND` and was reported as a registry
  outage. The import is now lazy on the kernel-bump path, with a bare-checkout regression test.
- **Tracker**: zero open issues and zero open pull requests before the release.
