# dsh-desktop v0.1.2-rc.1.shell.4

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` `0.1.2-rc.1`（未变，壳修订 +4）。

## 本次更新

- **真实世界的失败签名修复**：此前失败检测只匹配 `failed to apply loader entry`，而真实内核断崖（如 0.1.2-rc.1 移除 `installSettingsSection`）在日志中是 `failed to import loader entry`——错误页在真实场景下列不出嫌疑插件。现在同时匹配 import 变体与缺失包的 `cannot resolve profile bundle` 签名，本机实测你遇到的那种崩溃终于能在恢复中心逐个列出插件。
- **首次启动失败带完整日志**：崩溃页不再只有一行 supervisor 摘要，而是携带 harness 自身输出——嫌疑插件的判定依据来源就在这里。
- **内核断崖提示**：错误页按日志证据分类失败原因；识别为「插件引用了内核已移除的导出」时，提示文案直接说明升级插件通常即可修复。诊断报告新增 `failure_cause` 字段与对应动作建议。
- **恢复路径真实回归**：新增打包级 E2E——预置坏插件 → 崩溃 → 错误页点「升级」→ 真实 npm 安装 → harness 携新插件启动，全程真实 registry。
- **发布自动化**：合并 dsh-bump PR 即自动写发布说明、打 tag、触发完整发布门禁，发布成功自动派发 GitCode 镜像；官网 changelog 页改由发布说明自动生成。
- **边界说明**：恢复操作仍仅限壳自有错误页调用（Harness 页面无法触碰 bundle 清单）；官方内置包不可被升级/禁用。

## English Summary

- Fixed real-world failure signatures: the detector now matches the `failed to import loader entry` variant (the one actual kernel-API cliffs emit) and the missing-bundle `cannot resolve profile bundle` error, so the error page finally lists suspects in real crashes; a failed first boot now carries the harness's own output tail instead of a one-line summary.
- Kernel-cliff classification: the error page explains the missing-export cause and points at one-click Update; diagnostics reports `failure_cause`.
- New packaged E2E proves the full recovery loop against the real registry (damaged plugin → error page Update → real install → harness boots).
- Release automation: merging a dsh-bump PR now writes release notes, tags, and triggers the full gated pipeline, then dispatches the GitCode mirror; the site changelog is generated from release notes.
