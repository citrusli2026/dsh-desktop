# dsh-desktop v0.1.5-rc.2.shell.7

Bundled kernel `@deepseek-ai/dsh` 0.1.5-rc.2 (unchanged; shell revision +7).

## Changes

- **Runtime upgrade: Electron 43 → 44 and the bundled Node runtime 22 → 24 LTS.** The harness child process now runs Node v24.21.0 (pinned from the official dist with per-platform SHA-256, same mirror-verified bootstrap), and the desktop shell runs Electron 44.3.0. CI workflows move to Node 24 so local, CI, and shipped runtimes agree. Native addons remain prebuilt Node-API modules, so no ABI rebuild is required.
- **Crash-safe writes for kernel-shared files**: the shell's profile-manifest quarantine write and the Safe Mode overlay/suspects writes now go through a same-directory temp file + rename (`atomicWriteFile`). A plain truncate-then-write could leave a zero-byte profile manifest behind when a crash, quit, or concurrent kernel read landed inside the write window — the next harness boot then died with `SyntaxError: Unexpected end of JSON input` in `readProfileManifest`. This is the deterministic form of the Ubuntu Safe Mode smoke failures (#40/#41 family) and it is fixed at the write site rather than retried away.
- **Upgrade-residue analysis for the Windows installer**: docs/nsis-upgrade-residue-analysis.md documents how a damaged bundled `node.exe` (issue #39) can survive an NSIS upgrade, the mitigations shipped in shell.5, candidate fixes, and a six-case manual test matrix for Windows hardware.

## Verification

- 272 unit tests pass on Node 24 types; typecheck, runtime boundary (`Node v24.21.0; Electron ^44.3.0`), site check, and main/preload build pass.
- Dev E2E 16/16, packaged smokes (headless + real Harness UI), the Safe Mode break-injection smoke (`DSH_DESKTOP_SAFE_BREAK=1`), and market install E2E offline 1/1 + real 2/2, all on Electron 44 + Node 24.
- New unit test pins the atomic-write contract: after repeated manifest overwrites the kernel-facing file parses and no temp siblings survive.
- Lockfile regenerated under the documented pnpm 9 fallback (the pnpm ≥10 root-install stall) and validated with `pnpm install --frozen-lockfile` on pnpm 11.
- GitHub release assets, attestation, cross-version upgrade, and GitCode mirror checks run in the standard release pipeline.

## English Summary
