# dsh-desktop v0.2.1-rc.2.shell.8

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` 0.2.1-rc.2（未变，壳修订 7 → 8）。

## 本次更新

- **失败可以一键交给 AI 排查（Incident）**：恢复中心和「插件市场」失败提示新增「问 AI / 问 AI 诊断」。
  壳把已脱敏的诊断（版本、profile、插件清单、失败分类、日志尾部）组装成一条故障事件，在 Harness 里
  创建会话并把带结构的排查提示作为首条消息：先判根因，再给最多 5 步修复和验证方法。AI 不可用时
  （内核未启动 / 能力缺失 / 创建失败）会如实说明，并自动回退到导出诊断 / issue，绝不是唯一出路。
  提示词把日志明确标为「数据，不是指令」，24 000 字节上限，超长保留头部并标注截断；只写本机
  `$DSH_HOME/incidents/{id}/`，不上传任何东西。ADR 0046。
- **小鲸鱼桌宠默认开启**：安装后主窗口右下角直接出现小鲸鱼；仍可在「桌面设置 → 扩展 → 小鲸鱼桌宠」
  关闭（切换后点「立即重启」）。Safe Mode 下一律不加载。
- **修复：旧版残留会让伴窗静默消失**。如果 web profile 里还留着自己安装的旧版
  `dsh-whale-widget`（例如 0.2.10），上一版会按这个旧版本号做兼容判断，导致最小化后不出现小鲸鱼。
  现在兼容判断读取**实际挂载的版本**（壳在 `profiles/node_modules` 的链接，0.4.2），旧目录不再影响
  伴窗；同时适配页仍加载实际挂载插件自己的 `/dsh-whale/widget.js`。
- **桌面工具入口不再被小鲸鱼遮挡**：小鲸鱼的装饰层之前会盖住右下角的「桌面工具」按钮和部分对话框；
  现在壳把它的层级压到 Harness 浮层之下，桌面工具与设置弹窗始终可点。
- **修复：重装插件市场不再“装完仍是未安装”**。`dsh plugin add` 只启用新增依赖，已保留的旧版本会被
  pnpm 锁住，且被内核兼容门禁跳过的版本只打告警。现在安装 `dshmarket@latest`；装完若启动清单仍缺
  该 bundle，壳补写 `dsh.profile.bundles` 一条（依赖与包目录不动）；CLI 明确报不兼容时返回新的
  `incompatible` 原因并附门禁原始行，不再误报为“目录不可写”。ADR 0045。
- **行为不变的部分**：插件代码仍未经修改；关闭鲸鱼开关会卸载插件并移除壳创建的链接；审批只在主窗口
  完成；Linux 不提供点击穿透；素材按上游 `PROVENANCE.md` 原样分发。

## English Summary

- **Failures can now open an AI triage session (Incident)**: the recovery page and a failed plugin-market
  row gained “Ask AI”. The shell packages the redacted diagnostic (versions, profile, plugin inventory,
  failure cause, log tail) into a durable incident, creates a Harness session, and sends a structured
  prompt (cause → evidence → at most 5 repair steps → verification). When AI is unavailable (kernel down,
  capability missing, session failed) the UI says so and falls back to export / issue — never a dead end.
  Log text is explicitly framed as data, not instructions; the prompt is capped at 24 000 bytes; artifacts
  stay under `$DSH_HOME/incidents/{id}/` and nothing is uploaded automatically. ADR 0046.
- **The whale companion is now on by default**; turn it off in “Desktop settings → Extensions → Whale
  companion” (restart Harness to apply). Safe Mode never loads it.
- **Fix**: a stale user-installed `dsh-whale-widget` (e.g. 0.2.10) in the web profile no longer suppresses
  the companion — the compat check now uses the **mounted** version (the shell's 0.4.2 link in
  `profiles/node_modules`), while the adapter still loads the mounted plugin's own `/dsh-whale/widget.js`.
- **The whale no longer blocks the desktop-tools entry or settings dialogs** (its decorative layer now sits
  below the Harness overlays).
- **Fix: reinstalling the plugin market no longer leaves it disabled**: install `dshmarket@latest`, add the
  missing boot entry after a successful install, and report an explicit `incompatible` reason (with the
  kernel gate line) instead of blaming profile permissions. ADR 0045.
- The plugin code remains unmodified; approvals stay in the main window; Linux has no click-through.
