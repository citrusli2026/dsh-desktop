# dsh-desktop v0.1.1-rc.2.shell.10

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` 0.1.1-rc.2（未变，壳修订 +10）。
本版把 shell.9 之后合并的四条功能链整体发布，并补上发布前审查发现的 ADR 0026 启动路径回滚缺口。

## 本次更新

- **DeepSeek 余额读数（ADR 0025）**：托盘新增「余额：¥…」行，点击直达 DeepSeek 平台充值页；「设置 → 扩展设置」同样有一行只读余额 + 充值按钮。配置了 DeepSeek 密钥才显示，无密钥 / 网络失败 / 异常载荷时整行消失——不报错、不打空状态。按需拉取 + 5 分钟缓存，不后台轮询；密钥只留在主进程，只发往 DeepSeek 余额 API。
- **内核独立更新链（ADR 0026）**：不用等整个应用升级，可在「扩展设置」检查官方内核新版本、安装并切换（安装到应用数据目录，用随包 pnpm、与随包闭包一致的 hoisted 布局）。切换后的第一次启动做健康检查：90 秒内未就绪或启动失败，自动滚回随包内核、标记该版本失败、恢复中心全程可用——**坏内核永远困不住工作台**；「恢复内置内核」保留已安装版本供重试。随包内核始终是兜底地板。
- **首批 curated 插件种子 + 插件市场入口（ADR 0024）**：全新安装首次启动即备好三个精选社区 bundle——`dshmarket` 1.36.0（插件市场）、`dsh-better-sidebar` 0.17.1、`@linxin666/dsh-client-ui-task-board` 0.3.6——离线从随包闭包以符号链接种子进剖面，零 CLI 即可用市场。已有安装的「扩展设置」有「安装插件市场」一行（捆绑 dsh CLI，2 分钟超时，状态实时回显）。种子只在剖面清单不存在时触发一次：已有剖面绝不改写、用户卸载过的插件绝不装回，种子就是普通用户插件（设置 → 插件可管理，安全模式可隔离）。
- **opt-in 截屏工具（ADR 0027）**：「扩展设置」新增「截屏」偏好，默认关闭。开启后，会话可使用 `screen_capture` 工具：截图经官方附件服务提交进当前会话，**始终回填对话、绝不静默注入**；按平台使用系统 CLI（macOS `screencapture` / Windows PowerShell / Linux scrot 等），临时文件提交后即删除。官网 FAQ 同步更新隐私说明。
- **扩展入口只承载扩展动作（ADR 0023）**：桌面控件浮层、应用「扩展」菜单与托盘菜单统一为同样的三件套——手机配对 / 安全模式 / 关于；全屏归到原生 View 菜单；日志与诊断收敛进「关于」对话框；崩溃恢复页保留自己的日志与导出按钮（崩溃时它是唯一可达界面）。
- **健康保证修复（发布前审查）**：坏了的内核自动回滚此前只覆盖「手动切换内核」的路径——应用启动时若选中的 overlay 内核首次引导失败，会反复尝试坏内核并停在错误页。现在启动路径同样带一次性健康守卫：首次引导即失败 → 标记失败、清除选中、自动重启回随包内核；同一版本重装成功会清除失败标记。
- 全部为本地功能：余额密钥只在主进程与 DeepSeek 余额 API 之间流动；截屏默认关闭、只进用户所在的会话；内核安装在应用数据目录，与用户剖面隔离。

## English Summary

- **DeepSeek balance readout** (decision 0025): a tray line "Balance: ¥…" and a read-only row in Extension settings, both opening the DeepSeek platform top-up page; surfaces appear only when a key is configured, fetch on demand with a five-minute cache, and the key never leaves the main process.
- **Kernel overlay — the second update chain** (0026): check for, install, and switch to newer official `@deepseek-ai/dsh` versions from Extension settings without an app update. The switched kernel gets one health boot (90 s); on failure the overlay is marked bad and the shell rolls back to the bundled kernel automatically — the bundled closure stays the floor and a bad kernel cannot strand the user.
- **Curated first-run bundles and market entry** (0024): a brand-new profile boots with three curated bundles (dshmarket 1.36.0, dsh-better-sidebar 0.17.1, task-board 0.3.6) seeded offline from the vendored closure; existing installs get an "Install plugin market" row driven by the bundled CLI. The seed fires once — existing profiles are never rewritten and uninstalled bundles never come back.
- **Opt-in screen capture** (0027): a new default-off preference registers the `screen_capture` tool; screenshots enter the session through the official attachment service — always fed back into the conversation, never injected silently — and temp files are deleted after upload. The site privacy FAQ is updated accordingly.
- **Extension surfaces carry extension actions only** (0023): the overlay, the Extensions menu, and the tray expose the same trio (pairing / Safe Mode / About); fullscreen moves to the native View menu; logs and diagnostics live in the About dialog.
- **Launch-boot rollback fix** (pre-release review): the ADR 0026 "bad kernel never strands the user" guarantee now covers the boot at app start, not only mid-session switches; a failed launch boot marks the kernel failed and restarts on the bundled one, and a successful reinstall clears the version's failed marker.
