# dsh-desktop v0.1.2-rc.1.shell.5

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` `0.1.2-rc.1`（未变，壳修订 +5）。

## 本次更新

- **发布链路自愈**：release 或 GitCode 镜像任何一环失败都会自动开 issue（按标题去重，重复失败追加评论），不再出现“官网悄悄停在旧版本、没人知道”。Release 失败后官网数据同步也会照常兜底执行。
- **一键提交问题**：错误页新增「到 GitHub 提交问题」——自动预填版本、平台、内核、安全模式、疑似插件与失败原因，全部脱敏，不含日志原文或路径；诊断报告由你自己导出并拖进 issue，应用不会自动上传任何文件。
- **升级结果语义修正**：插件已是最新可获得版本时，错误页显示「已是当前可获得的最新版本,正在重启…」，不再让人误以为升级失败（registry 元数据可能滞后于刚发布的 dist-tag）。
- **边界说明**：支持入口只在壳自有错误页出现；预填内容不包含密钥、日志或用户路径。

## 验证

- 单元测试 210 通过（新增支持页 URL 构造与脱敏用例、错误页新动作与三态断言）；`pnpm run verify` 全绿。
- E2E 15 通过（插件恢复全链路 + LAN 二维码本机门禁）；真实 registry 恢复升级 E2E 复验通过。

## English Summary

- Release-chain self-healing: release.yml and gitcode-backfill failures now open (or append to) a GitHub issue automatically, and a failed Release run no longer skips the site data sync.
- The error page gains "Open a GitHub issue", prefilling sanitized context (version/platform/kernel/Safe Mode/suspects/cause) — never log text or paths; the diagnostic file is attached by the user only.
- Plugin Update now resolves "current" when the install was a no-op and the error page says the plugin is already the newest obtainable version, instead of implying failure.
