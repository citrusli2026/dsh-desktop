# dsh-desktop v0.1.1-rc.2.shell.12

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` 0.1.1-rc.2（内核不变，壳修订 +12）。

## 本次更新

- **插件市场开箱即用**：新安装首次启动会准备社区插件市场 dsh-market，并带上 Better Sidebar、任务看板两个精选扩展；在 Harness「设置 → 插件市场」中即可浏览、安装和更新，不需要命令行。老版本可从「设置 → 扩展设置 → 插件市场」补装。
- **扩展入口统一**：窗口右键菜单、托盘、扩展菜单和浮层都提供「安全模式」与「重启 Harness」；浮层的「连接设备」会跟随配对状态显示二维码或停止共享，安装插件后可以从任一入口重启生效。
- **真机更新链更可靠**：插件与内核安装使用应用自带的 pnpm，并透传系统代理；注册表、余额和更新检查都有明确的超时与失败反馈，避免图形界面启动时因系统 PATH 缺少 pnpm 而无响应。
- **跨平台细节修复**：macOS 在屏幕捕获前检查录屏权限，Windows 通知补齐 App User Model ID，失效的配对二维码窗口自动关闭，安全模式启动失败后的重试按钮会恢复可用。
- **本地边界**：插件安装、配对、诊断和偏好设置均由本地桌面壳控制；桌面通知不读取屏幕、不自动上传数据，第三方插件仍需用户明确授权其构建脚本。
- **稳定性修复**：注册表超时采用显式可清理的计时器，确保在真实网络和无网络测试环境中都能可靠结束更新检查。

## 验证

- 本地 `pnpm run verify` 全绿：TypeScript 类型检查、181 项单测与覆盖率门禁、双语官网检查、实时下载 API 检查和构建均通过。
- GitHub Release 门禁继续执行 Electron E2E、macOS/Windows/Linux 三平台打包、安装包冒烟、安全模式故障恢复和来源证明校验；每个平台安装包均附带 SHA-256 校验文件。

## English Summary

- **Plugin market out of the box:** fresh installs seed dsh-market plus Better Sidebar and Task Board; users can browse, install, and update community plugins and themes from Harness settings without a terminal. Older installs can add it from Extensions settings.
- **Consistent extension surfaces:** Safe Mode and Restart Harness are available from the context menu, tray, extensions menu, and overlay; the overlay pairing action follows the live pairing state.
- **More reliable real-machine updates:** plugin and kernel installs use the bundled pnpm with system-proxy passthrough, while registry, balance, and update checks now have bounded, user-visible failure behavior.
- **Cross-platform fixes:** macOS checks screen-recording permission before capture, Windows notifications set an App User Model ID, stale pairing windows close themselves, and Safe Mode retry controls no longer get stuck.
- **Local boundary:** plugin installs, pairing, diagnostics, and preferences stay under the local desktop shell; notifications do not read the screen or upload data, and build scripts still require explicit user approval.
- **Stability:** registry timeouts use an explicit, cleaned-up timer so update checks terminate reliably in both real networks and isolated test environments.
