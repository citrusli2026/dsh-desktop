# 0014:渲染层权限默认拒绝

- 日期:2026-08-15
- 状态:已接受
- English: [0014](0014-deny-renderer-permissions-by-default.md)

## 背景

Harness 界面从回环 HTTP 地址加载到沙箱化的 `BrowserWindow`。现有的上下文
隔离、沙箱、关闭 Node 集成、导航守卫和单方法 preload 桥已经限制了渲染层
能力,但 Electron 会话级的 Web 权限此前没有显式处理。上游页面仍可能请求
媒体、定位、通知、屏幕采集、USB、串口或文件系统权限,并依赖各平台默认值。

## 决策

在创建主窗口前同时安装 Electron 的权限检查与权限请求处理器。权限检查
一律返回 `false`,权限请求一律以 `false` 回调。当前桌面壳不需要这些权限;
未来功能若确实需要某项权限,必须增加范围明确、有文档且有测试的白名单,
而不是放宽默认规则。

## 后果

- 正面:渲染层能力变得显式且跨平台一致;上游意外发起的权限请求无法越过
  桌面壳预期的安全边界。
- 负面:未来 Harness 若新增确需 Web 权限的能力,桌面版会暂时不可用,直到
  壳层完成审查并明确放行。

## 备选方案

- 依赖 Electron 与操作系统默认值:拒绝,因为默认值会变化,也不能表达产品
  的安全契约。
- 对回环来源放行全部请求:拒绝,因为信任来源不等于需要全部高权限浏览器
  能力。
