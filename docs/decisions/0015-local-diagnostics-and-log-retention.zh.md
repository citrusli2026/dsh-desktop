# 0015:本地诊断报告与有界日志保留

- 日期:2026-08-15
- 状态:已接受
- English: [0015](0015-local-diagnostics-and-log-retention.md)

## 背景

受监督的 Harness 进程会持续写入 `harness.log`,但原先没有文件大小上限,用户
也只能自行定位和检查日志。成熟的开发者工具会让故障状态能够被检查并附到
问题报告中。与此同时,诊断信息可能包含路径、提示词或凭据,自动上传会违背
桌面壳的本地优先边界。

## 决策

- `harness.log` 超过 5 MiB 时轮转,保留三代编号日志。
- 用户可从帮助菜单、托盘或内置错误页导出一份纯文本报告。报告包含产品与
  运行时版本、操作系统与架构、Supervisor 状态,以及最多最近 256 KiB 日志。
- 尽力遮罩用户主目录和常见形式的凭据。
- 导出前说明报告内容,只保存到用户选择的本地路径,绝不自动上传。

## 后果

- 正面:磁盘占用有明确上限,支持报告也带有一致的上下文。
- 正面:诊断内容的去向始终由用户控制。
- 负面:遮罩不是“绝不含敏感信息”的证明,界面必须继续提醒用户分享前检查。
- 负面:纯文本不如压缩包紧凑,但透明、无需新增依赖且便于直接检查。

## 备选方案

- 压缩全部应用数据:拒绝,因为会收集远超排障所需的隐私状态,还会引入依赖。
- 自动上传到托管端点:拒绝,除非未来有明确的隐私政策、同意流程、保留策略和
  运维责任人。
- 日志不设上限:拒绝,因为长期驻留托盘的应用必须有可预测的存储边界。
