# 0028:扩展面增加重启动作

- 日期:2026-08-30
- 状态:已接受
- English:[0028](0028-extension-surface-restart.md)

## 背景

决策 0023 把扩展面收敛为三元动作(连接设备/安全模式/关于),但没有覆盖
一个高频场景:安装、升级或排障插件之后,需要重启 Harness 让新的 bundle
列表生效。目前重启只存在于托盘与帮助菜单;扩展入口浮层、窗口右键菜单
和应用「扩展」菜单都没有——在浮层里装完插件,还得去别处找重启。

## 决策

每个扩展面——扩展入口浮层、应用「扩展」菜单、托盘菜单、窗口右键菜单
——在三元动作之外增加第四个动作:**重启 Harness**(决策 0023 的三元组
不变,顺序为 连接设备 → 安全模式 → 重启 → 关于)。

- 重启走同一条路径:`ShellApp.requestRestart()`,Harness 处于就绪状态时
  先弹确认框(重启会中断运行中的任务),与托盘/帮助菜单现有行为一致;
- 浮层通过新的 `restartHarness` 桌面动作触发,面板立即关闭,确认框由
  主进程弹出;
- 不提供"不确认直接重启"的变体:插件刷新值得一次点击的确认代价。

## 后果

- 正面:四个扩展面动作完全一致,装完插件顺手重启;"重启"与"安全模式"
  一起构成排障闭环;
- 负面:扩展面动作从三元变四元,决策 0023 的"三元组"表述由本决策修正;
- 中性:托盘与帮助菜单的原有重启入口保持不变,不迁移、不删除。

## 备选方案

- 只在浮层加重启(最小改动):扩展面再次漂移,正是 0023 要消灭的——否决;
- 在扩展设置里加"重启"按钮:重启是动作不是偏好,放设置页语义错位——否决;
- 自动在插件安装后静默重启:安装已有"重启以生效"的确认语义,静默重启
  会打断正在运行的任务——否决。
