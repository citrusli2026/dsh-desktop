# 0021：安全模式、恢复中心与便携预设包

- 日期：2026-08-28
- 状态：已接受
- English：[0021](0021-safe-mode-recovery-presets.md)

## 背景

一个损坏的第三方插件就能让整个 profile 无法启动：Harness 渲染失败，而桌面壳
目前只有"重试"这一条恢复路径。社区对此的解法是非破坏性 Safe Mode（dataelement）、
健康检查点+恢复页（anywhere-labs），或快照+自动修复（EAC）。另一方面，Agent
预设是上游的一等概念，有基于信任根的挂载模型，但上游没有导出/导入能力，预设
既不能随身携带也无法在 Agent 之间共享。shell.9 把这些归到"救援与分享"一个主题
下；本主题不得删除或改写用户插件文件，也不得复制官方已有的 WebUI/视觉能力。

## 决策

1. **安全模式是壳拥有的启动形态。** 安全模式运行的插件树组成为：官方
   `dsh.profile.bundles` + 壳自带 `dsh-desktop-controls` 覆盖层 + 一个禁用
   profile 中全部用户插件条目的安全模式覆盖层。用户插件不加载；用户插件
   文件、profile 的 `package.json` 与 `cordis.patch.yml` 一律不删除、不移动、
   不改写。继续使用同一个 DSH_HOME，会话、`settings.yaml` 与 API 凭据不受影响。
2. **双触发。** 自动：Harness 未达到就绪、崩溃循环超过重启预算，或在输出中
   出现插件加载失败签名（精确签名由 spike 钉死；超时与崩溃循环始终是兜底）。
   手动：扩展入口与「扩展设置」行提供「以安全模式启动」桌面动作。进入安全模式
   即停止 Harness并以安全参数集重启。
3. **安全模式保持到用户显式退出。** 标志存于 `shell-preferences.json`；窗口横幅
   与「扩展设置」行显示当前状态并提供「退出安全模式」，退出即恢复正常参数集重启。
   未退出前的重启保持安全模式，避免坏插件在开机时再次击垮应用。
4. **恢复中心。** 错误恢复页升级为四动作中心：重试（语义不变）、以安全模式启动
   （已在安全模式时隐藏）、导出诊断、打开日志文件夹。所有动作走既有带发送方校验
   的 `desktop:action` 桥。
5. **诊断增强。** 导出报告新增：profile 插件清单（profile 依赖 + patch 条目）、
   从 Harness 日志错误签名提取的疑似坏插件候选、当前安全模式状态、捆绑的壳/内核
   版本。报告保持纯本地（决策 0015）。
6. **便携预设包（`.dshpreset`）。** 把已挂载的 Agent 预设导出为单个包文件；导入
   先对预设 id 做冲突检测（跳过 / 覆盖 / 以新名字克隆），并对非官方预置根的预设
   显示信任警告——复用上游已有的信任根区分。导入后的预设经官方预设选择器挂载，
   Agent 模型与 Harness 行为不变。范围只限本地静态文件的导出/导入；不做市场或
   远程下载。
7. **诊断结果壳内查看。** 导出的包可在壳内纯文本查看报告正文与 `harness.log`。
   通用文件预览（PDF/CSV/图片等）本轮不做——那与官方附件/工作区查看重叠。

## 后果

- 正面：坏插件不再击垮 profile，引导式恢复（重试 → 安全模式 → 导出 → 日志）
  给非专家用户一条回来路。
- 正面：诊断以插件清单加日志候选直接回答"哪个插件坏了"，不再手动翻日志。
- 正面：Agent 预设通过一个静态文件即可携带与分享，冲突处理与信任警告由壳承担。
- 正面：全程非破坏、升级安全；用户插件数据与 Harness 配置永不被修改。
- 负面：自动检测依赖 Harness 输出文本，上游可能改写措辞；spike 钉下今天的
  签名，超时/崩溃循环路径始终兜底。
- 负面：安全模式一次性隐藏全部第三方插件——用户仍需定位肇事者（清单+候选已
  缩小范围；官方「设置 → 插件」仍是修复面）。
- 负面：预设信任警告是壳层的出处标注，不是代码级沙箱验证。
- 负面：安全模式新增一个需在三平台打包 smoke 覆盖的启动状态，且是一个用户
  可能忘记的模式——持续横幅缓解。

## 备选方案

- 临时重命名用户插件目录：恢复中途崩溃会留下移了一半的插件、与 hoisted pnpm
  链接冲突、并和并发访问竞争——被拒绝，改用 loader 组合覆盖层。
- 专用 Safe profile（`--profile`)：profile 隔离数据，会话、设置与 API 凭据会被
  隐藏——被拒绝。
- 自动删除坏插件：破坏性、修改用户数据、无法判断意图——被拒绝；官方插件管理器
  保持为修复面。
- 检查点快照+自动回滚（anywhere-labs/EAC 式）：重，且越过"不改变 Agent 行为"
  的壳边界——推迟。
- 通用文件预览（PDF/CSV/JSON/YAML）：与官方附件/工作区预览重叠——推迟。
- 预设市场或远程下载：远超"一个静态文件"的供应链面——本轮拒绝。
