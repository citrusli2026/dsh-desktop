# 0011:壳体验打磨——重试恢复、窗口状态持久化、托盘面

- 日期:2026-08-15
- 状态:已接受
- English:[0011](0011-shell-ux-polish.md)

## 背景

0.1.0-rc.6.shell.3 之后的一次壳层审查发现若干缺口,均不涉及 harness
行为。其中三个在本篇处理;第四个——macOS 完全没有更新信号——在
[0010](0010-macos-check-only-update.zh.md) 单独处理:

1. **重试可能把错误页卡死**:`harness:retry` 在重启未达到就绪时 resolve
   `false`,但页面只处理了 Promise rejection——按钮永远停在"正在启动…";
2. **窗口永远以 1280×860 打开**,不记忆用户调整的几何状态;
3. **托盘只有打开/退出**——没有状态、没有重启、没有诊断入口。

## 决策

1. **重试恢复**:错误页在所有失败形态下都恢复按钮——resolve `false`、
   rejection、preload 桥缺失——并用一行提示说明。新增仅 smoke 使用的开关
   (`DSH_DESKTOP_TEST_RETRY_FAIL=1`)强制走 `false` 路径,CI 据此做回归。
   重启逻辑抽为共享的 `restartHarness()`,托盘的重启项复用它。
2. **窗口状态**:普通 bounds 与最大化标志持久化到
   `userData/window-state.json`(resize/move 防抖写入,关闭时精确写入)。
   几何规则是纯函数(`src/main/window-state.ts`):尺寸钳制到窗口最小值;
   仅当保存的位置在任一已连接显示器上仍可见至少 100 px 时才复用;输入
   畸形时回落默认值。
3. **托盘面**:状态行(启动中/运行中/已崩溃)、重启 Harness、打开日志
   目录、检查更新…(行为见 0010)、当前版本号。每次 supervisor 状态跃迁
   时重建菜单。

## 后果

- 正面:崩溃恢复不会再把用户困在死按钮上;窗口记忆几何状态;harness
  状态与生命周期操作从托盘可见;
- 负面:壳自身文案(页面、托盘、弹窗)目前仍只有中文。

## 备选方案

- 就绪后轮询 harness 健康端点(进程活着但 HTTP 挂死):暂缓——一个会
  误杀"忙但慢"的 harness 的看门狗比它要补的缺口更糟;
- 壳页面完整 i18n:暂缓,直到真有第二种语言的需求。
