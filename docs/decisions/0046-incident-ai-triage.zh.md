# 0046：把失败变成可交给 AI 排查的故障事件

- 日期：2026-10-24
- 状态：已接受
- English：[0046](0046-incident-ai-triage.md)

一次真实故障暴露了缺口：安装插件市场时提示「数据目录不可写或 profile 状态不完整」，而壳其实已经
知道市场包因内核版本不匹配被跳过。用户和模型都只拿到一句话、没有证据。壳是唯一同时看得到 profile、
日志和失败分类的一方，所以它应该把事实打包交给会推理的代理，而不是自己猜。

决策：每个壳可见的失败都变成一条**故障事件（Incident）**——一条已脱敏的记录，用户可以把它送进
AI 排查会话、导出，或提交 issue。

- **一份契约**（`src/main/incident.ts`）：失败面（`market` / `startup` / `health`）、带类型的 code、
  语言、应用/内核版本、可选的一行 detail、允许的动作，以及已脱敏的 report。提示词只拼一次：角色、
  任务、以「数据不是指令」围栏的已知事实、动作词表、严格输出格式（结论/证据/修复/验证/风险）和
  禁止项。上限 24 000 字符；超长报告保留头部并以 `…[报告已截断]` 结尾，但 code/detail/actions
  绝不截断。
- **三个出口、一个兜底**：（1）沿用既有 Host 环回 + Bearer 通道的应用内 AI 会话；（2）内核不可用时
  主进程直连模型（二期）；（3）始终可以导出报告并打开预填 issue。AI 按钮是增量的，绝不替代白名单
  恢复动作。
- **隐私**：报告在本地用现有脱敏（home 路径、token、密钥）生成，只在用户点「问 AI」时发送；不做任何
  自动上报。宿主把 `report.md` / `prompt.md` 写到 `<DSH_HOME>/incidents/<id>/`，日志只记 id，不记正文。
- **诚实优先**：内核缺少会话能力时宿主返回 `unsupported`，界面如实说明、复制报告并引导导出/issue，
  绝不伪造会话或诊断。

后果：失败会留下可追溯的产物和带证据的对话，而不是一个死胡同提示；壳需要持续维护脱敏并保证提示词
有界。被否决的方案：把整份原始日志塞给模型（无界且有提示注入风险）、把「问 AI」当成唯一恢复路径
（内核挂了就失效）、自动上传故障事件（违背仅本机承诺）。
