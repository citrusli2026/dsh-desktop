# 0048：热重载安全的 webserver 路由注册

- 日期：2026-10-25
- 状态：已接受
- English：[0048](0048-reload-safe-routes.md)

上游 `dsh-whale-widget` #268：切换插件时，内核会在**销毁上一次执行之前**重新运行插件的 `apply`
（Cordis `Fiber._reload`）。小鲸鱼注册了 `/dsh-whale/image.png` 等精确路由，第二次执行就命中
`webserver: duplicate exact route "/dsh-whale/image.png"`，桌面端随后重启。插件无法改变这个顺序，
壳也不能为了修它去改随包插件（会破坏 ADR 0044 的“上游代码不改”）。

决策：壳的宿主插件在**最早的 patch 位置**安装一层“热重载安全”的路由守卫，先于第三方插件生效。

- 每个 webserver 实例只包一次 `register`（状态放在 `globalThis`，因此本插件自身重载后仍在），
  并记住自己创建的每个 disposer。
- 再次注册同一 `(kind, path)` 时先调用旧 disposer，再注册新路由；首次注册、正常 dispose、其他路径
  行为完全不变。
- 服务不可包装（冻结/代理）时只记一条日志，不破坏启动。
- 范围：只覆盖守卫安装后**经由该服务**注册的路由；桌面 patch 顺序里此前没有路由，仍由内核的重复
  检查兜底。
- 守卫不碰配置、插件代码或响应处理，只让路由所有权在重载时可替换。

后果：切换插件不再把重复路由变成桌面重启；壳承担一个有文档的小兼容层。被否决：修改随包鲸鱼
（违反 ADR 0044）、关闭热重载（牺牲其他插件开关）、只吞掉错误但不替换路由（旧 handler 会继续
提供过期状态）。

测试：单测覆盖替换/dispose/冻结服务；打包的鲸鱼与伴窗用例确认守卫不影响正常注册。Cordis 实际
重载没有稳定的自动化钩子，因此未做端到端重载用例。
