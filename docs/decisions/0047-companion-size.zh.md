# 0047：桌面伴窗使用独立大小

- 日期：2026-10-25
- 状态：已接受
- English：[0047](0047-companion-size.md)

内置小鲸鱼沿用插件的 `.dshw-size.json` 缩放。主窗口的基准尺寸来自视口
（`clamp(122px, min(100vw, 100vh) * 0.28 * scale, 625px)`）；在 560×620 的伴窗里这个公式会落到
122 px 下限，上一版适配页用写死的 1.6 去补偿，结果同一缩放值下伴窗远大于主窗口，而且改一个会
影响另一个。

决策：桌面伴窗使用**独立的大小偏好**（`whaleCompanionSize`，80–400 px，默认 160），不再从主窗口
推导。

- 壳把该偏好与其他桌面设置一起保存；设置页在鲸鱼开关下提供滑杆，并注明只影响最小化后的伴窗。
- 伴窗 URL 只对壳自有的适配页追加 `dshCompanionSize=<px>`；第三方插件自己的伴窗页面不受影响。
- 适配页用 `!important` 固定 `--dshw-scale: 1` 与 `--dshw-base: <px>`（按窗口夹取），因此同一个
  数值在任何窗口尺寸下都是同一像素大小。
- 主窗口继续使用插件自己保存的缩放；两者按设计互相独立。
- E2E 以 220 px 为种子，断言伴窗根节点 220 px、`--dshw-base` 为 `220px`，同时主窗口仍是保存的
  0.6 缩放。

后果：用户可以把桌面鲸鱼调到舒服的大小而不影响窗口内挂件；设置仅本机生效、不影响第三方伴窗，
且只需重新最小化（重新打开伴窗），不需要重启 Harness。被否决的方案：共用保存缩放（视口公式让
相同数值看起来不同）、写死伴窗倍率（shell.8 的做法，正是本次问题的来源）。
