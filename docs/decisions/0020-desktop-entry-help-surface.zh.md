# 0020: 桌面入口帮助浮层与通知点击聚焦

- 日期: 2026-08-28
- 状态: 已接受
- 英文：[0020](0020-desktop-entry-help-surface.md)

## 背景

shell.4 引入应用内 `⋮` 入口，让 Windows 用户在没有可见菜单栏时也能进入 LAN
配对、全屏和关于。shell.6 增加了桌面状态通知，但点击通知只显示、无任何处理
——窗口藏在托盘时，“任务已完成”的通知无法把用户唤回对话。遗留两个小缺口：
诊断报告与日志只有托盘/菜单可达；唤起快捷键只在 Harness 设置页显示。

## 决策

1. `⋮` 面板升级为完整的桌面帮助浮层：在 LAN 配对、全屏、关于之外增加
   “打开日志文件夹”与“导出诊断报告”，复用托盘/菜单完全相同的动作，走同一个
   白名单 `desktop:action` 桥；面板每次打开时从壳偏好快照重新读取并显示当前
   唤起快捷键。托盘、窗口右键与应用菜单原有入口一概保留。
2. 桌面状态通知点击后显示并聚焦主窗口——单一而明确的动作；不跳转到对应会话、
   不读取内容、不操作 Harness。
3. 桥保持窄且校验来源：新动作只是同一个 switch 中的字符串分支，发送方校验、
   单一布尔返回值，与既有三项完全一致。

## 后果

- 正面：Windows（及其他平台）用户无需翻找托盘即可到达日志与诊断报告；帮助
  浮层是唯一可预期的地方。
- 正面：点击通知总能回到工作区，三平台均符合原生通知惯例。
- 负面：由 Web 渲染层触发的“导出诊断”仍会弹出保存对话框；对话框是主进程控制
  的原生界面。
- 负面：面板略长；固定样式的提示文案保持紧凑。

## 备选

- 点击通知跳转到对应会话：通知只携带会话标题/id，映射到前端视图属于 Harness
  内部细节；上游未提供稳定链接前不做。
- 用面板替换托盘/菜单入口：会移除本项目的硬边界——原生降级路径。
