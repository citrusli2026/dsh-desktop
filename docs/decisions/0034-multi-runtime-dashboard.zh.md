# 0034：采用明确 Edition Adapter 的多 Runtime Dashboard

- 日期：2026-10-08
- 状态：已接受
- English：[0034](0034-multi-runtime-dashboard.md)

## 背景

dsh 生态同时存在多个桌面壳和多个官方 `@deepseek-ai/dsh` 版本。单一的
`active.json` 与单一 `DSH_HOME` 无法安全表达并行环境。社区桌面应用也不能被
当作 npm runtime：它们有各自的安装器、更新链、数据策略和信任边界。

## 决策

Dashboard 使用三个明确概念：

- **Edition**：官方或社区桌面/Runtime 来源的目录条目；
- **Runtime**：已安装的 `@deepseek-ai/dsh` 版本或其他受支持的可执行来源；
- **Environment**：拥有独立 `DSH_HOME`、workspace、端口和生命周期的命名进程实例。

首版先管理官方 npm runtime。每个环境显式选择 runtime，不修改桌面的全局
active 指针。多个环境可以并行运行；卸载 runtime 不删除环境数据；运行中的环境
会阻止 runtime 卸载。

未来接入社区桌面 Edition 时，必须使用明确的 Adapter，描述安装、启动、停止、卸载、
更新、支持平台、数据路径和信任元数据。Dashboard 不复制社区桌面代码，也不静默执行
任意社区二进制。

隔离按等级显示：L1 数据目录、L2 进程/端口、L3 安装根目录、L4 OS sandbox。首版只
承诺 L1–L3；L4 需要单独的平台安全专项。

## 后果

- 当前产品仍是可靠 Electron 壳，不变成 Agent 工作台；
- 多个官方版本可以并行安装和运行，不影响主 Harness 指针；
- 可以展示社区版本，但目录没有静默安装或更新软件的权限；
- 卸载 runtime 后仍保留环境数据，用户可以重新安装版本或导出环境；
- Dashboard 除版本号外，还需要来源和信任元数据。

## 备选方案

- **继续使用单一全局 runtime 指针**：否决，无法支持并行环境和安全的数据归属；
- **把所有社区桌面项目复制进本仓库**：否决，会产生不可维护的分叉并混淆维护责任；
- **把目录隔离宣传成安全沙箱**：否决，目录/进程隔离只能减少误串扰，不能防御恶意代码；
- **让远程目录直接安装它列出的内容**：否决，发现与执行必须分开并经过用户确认。
