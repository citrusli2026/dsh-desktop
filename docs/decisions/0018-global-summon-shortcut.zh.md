# 0018：桌面全局快捷键快速唤起

- 日期：2026-08-26
- 状态：已接受
- English：[0018](0018-global-summon-shortcut.md)

## 背景

dsh-desktop 关闭窗口后默认驻留系统托盘。托盘适合持续运行，但用户在编辑器、终端
或浏览器中工作时，必须先寻找托盘图标才能回到 Harness。上游 Harness 是本地 Web
UI，不能替桌面壳注册操作系统级的唤起快捷键。

## 决策

1. 发布版默认注册 `Ctrl/Cmd + Shift + Space`，按下后只执行“显示并聚焦 dsh-desktop”，
   不切换隐藏状态，避免用户误触后找不到窗口。
2. 快捷键注册属于主进程桌面能力，不向 Harness 渲染层暴露新的权限或桥接；退出时
   只注销本项目拥有的组合键。
3. 组合键被其他程序占用或系统不支持时，应用继续正常启动，并在托盘中显示不可用
   状态；托盘、窗口右键和应用菜单仍是完整的备用入口。
4. 冒烟测试不注册真实全局快捷键，避免测试进程影响运行测试的桌面环境；纯函数单测
   覆盖组合键、冲突和释放路径。

## 后果

- 正面：应用藏到托盘后仍可从任意桌面位置快速回到工作台，尤其适合长时间运行 Agent。
- 正面：快捷键冲突不会影响 Harness 启动，用户始终有可见的托盘与菜单入口。
- 负面：固定组合键可能与用户软件冲突；本版只提示不可用，不提供自定义。
- 负面：全局快捷键只在 dsh-desktop 运行时有效，不能唤起未启动的应用。

## 备选方案

- 仅在应用菜单声明 accelerator：应用隐藏后菜单不可见，不能解决桌面唤起问题——否决。
- 使用 `Ctrl/Cmd + J`：容易与浏览器下载或上游 Web 快捷键产生冲突——否决。
- 默认开机自启：改变用户系统行为，且与本轮“按需唤起”的最小范围不一致——暂缓。
- 做视觉识别或截图入口：不属于本项目桌面壳定位，且官方已有相关能力——否决。
