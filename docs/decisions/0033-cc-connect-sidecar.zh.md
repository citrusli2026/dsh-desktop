# 0033：cc-connect 作为用户主动启用的桌面消息 Sidecar

- 日期：2026-10-07
- 状态：已接受
- English：[0033](0033-cc-connect-sidecar.md)

## 背景

用户需要从飞书发起和控制 DSH 任务，但桌面壳不应因此变成第二套 Agent
工作台。cc-connect 已经负责消息平台适配，并能通过官方 ACP stdio 协议驱动
Agent。因此，DSH 继续拥有 Agent、工具、权限和会话语义；桌面壳只负责打包、
配置、凭证和进程监管。

## 决策

飞书集成采用由 dsh-desktop 管理、由用户主动启用的 cc-connect Sidecar。
Sidecar 启动官方 DSH ACP 进程，并通过 ACP stdio 通信。Web Harness 与 ACP
进程使用同一个桌面 `DSH_HOME`，但保持独立进程；集成不复制 Harness 会话模型，
也不调用 Web 内部接口。

集成只出现在桌面设置页，不加入浮层、托盘或扩展/桌面工具动作集合。只有用户
启用且配置完整后，桌面进程才启动 Sidecar；Web Harness ready 后才启动。
进入安全模式时停止 Sidecar，退出安全模式后若配置仍完整则恢复。安全模式停止
Sidecar 时保留用户的启用设置。

凭证只经由桌面主进程和 Sidecar 环境变量跨越边界。生成配置只包含 Secret
占位符，不写入飞书 App Secret。渲染层可以保存新 Secret，只能获知是否已配置，
不能读回 Secret。主进程优先使用 Electron 受保护存储，不可用时使用权限受限的
本地回退存储。Sidecar 日志和对外错误必须替换 Secret、token 及环境值。

首版范围是一个飞书长连接、一个项目和一个默认工作区，包含文本、现有附件降级、
工具进度、权限选择、停止任务，以及列出和恢复持久会话。不包含其他消息平台、
cc-connect 管理台或 webhook、ACP 模型/推理强度选择、原生 ACP 图片块、把 ACP
实时嵌入 Web Harness，或自动导入和接管用户已有的全局 cc-connect daemon。

本决策是对 ADR 0023 的局部补充：消息配置属于设置面，不属于扩展动作，因此三个
扩展面保持不变；也是对 ADR 0030 的局部补充：壳只打包和监管 Sidecar，不成为
Agent 工作台或会话权威；同时沿用 ADR 0031 的设置面和本地优先边界。

本文记录目标边界，不宣称集成已经实现，也不宣称人工飞书验收已经通过。

## 后果

- DSH 继续作为 Agent 执行和持久会话语义的唯一权威，降低桌面端和消息端行为
  分叉的风险。
- 配置完成的桌面实例可以提供受监管的飞书入口，同时不把凭证暴露给渲染层，
  也不增加新的全局动作。
- 共享 `DSH_HOME` 让 Web 与 ACP 使用同一套 DSH 安装状态；独立进程则保持各自
  生命周期清晰。
- 首版平台和项目范围刻意收窄；更广的平台支持或更丰富的 ACP 界面需要单独决策。
- 安全模式可以停止消息连接，同时保留启用意图，使恢复过程明确且可逆。

## 备选方案

- **在 dsh-desktop 中重写 Agent/会话循环**：否决，会复制 Harness 语义并产生
  第二个事实来源。
- **把 cc-connect 放进浮层或托盘**：否决，消息配置不是 ADR 0023 定义的共享
  扩展动作。
- **运行或导入用户的全局 cc-connect daemon**：否决，桌面只应监管自己打包的
  进程，也不能修改用户现有的全局配置。
- **把 App Secret 写进生成的 TOML 或渲染层状态**：否决，配置文件和渲染层都不
  是凭证存储。
