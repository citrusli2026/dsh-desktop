# 0031：轻量首次成功引导与本地优先运行体检

- 日期：2026-09-04
- 状态：已接受
- English：[0031](0031-first-success-guide-and-local-health-check.md)

## 背景

桌面壳的视觉体系已经基本一致，但桌面专属能力藏在名为“扩展”的入口后面。新用户
打开官方 Harness UI 后不知道下一步；运行时或 Profile 异常时，用户又需要从多个
恢复入口自行拼凑证据。

拦截式向导会与 Harness 自己的首启提示叠加，也容易让人误以为必须先安装社区插件。
自动修复工具则会越过壳层“不破坏用户数据”的边界。

## 决策

可见壳入口改名为**桌面工具**，对应设置页改名为**桌面设置**。

在主界面入口旁增加一次性、可关闭、非模态的轻量引导，展示四步：运行环境就绪、
选择工作区、配置模型、完成第一条任务。前三步只从 Harness 公开会话摘要在本地派生；
主进程在检测到既有非空成功会话，或真实的“运行中 → 已完成”边沿后，独占写入首次
任务完成状态。渲染层可以关闭引导，但不能伪造任务完成。插件市场明确标记为可选项，
不进入首次成功必经路径。

在桌面设置顶部增加用户主动触发的运行体检：

- 本地检查覆盖随包运行文件与版本、两个数据根的可写性和磁盘空间、Harness 就绪与
  loopback 连接，以及 Profile、插件、市场、安全模式和内核状态；
- 代理、npm registry 和更新源只有在用户勾选后才探测，连通性失败保持为建议性警告；
- 结果用“正常 / 警告 / 失败”和下一步动作表达，只保留在内存中；不返回路径、URL、
  日志、代理地址和捕获到的错误，也不上传；
- 所有检查只读，不修复、删除、移动或重写用户文件。

## 后果

- 新安装有清晰下一步，但不会再叠加一个阻塞弹窗。
- 已有成功会话的存量用户不会被重新打扰。
- 常见环境问题可先在本地分类，再决定是否导出范围更广的诊断报告。
- 联网行为继续显式、可选；体检不会膨胀成第二套配置或修复系统。

## 备选方案

- **拦截式首启向导**：否决，Harness 已负责账户、模型和会话配置，弹窗叠加会恶化首启。
- **首次使用前必须安装插件市场**：否决，所有社区插件仍应按需、手动安装。
- **体检失败后自动修复**：否决，可能在上下文不足时改动用户 Profile 或系统权限。
- **每次体检都访问外部服务**：否决，本地诊断不应静默发起网络请求。
