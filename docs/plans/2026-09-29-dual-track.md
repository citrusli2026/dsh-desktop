## 交给后续模型的规则

1. 先读本文件、目标路线 README 和 progress；执行 progress 标出的下一项。
2. 一次只实现一个任务。每项有前置条件、允许修改范围、验收和失败处理，全部满足才标 done。
3. 计划中的“新增文件/新增命令”是待实现规范，不是已经存在的工具；先完成定义它的任务，再运行对应命令。
4. 不因网络、环境或上游构建失败，顺手升级依赖、改包管理器主版本、跳过验证或重写锁文件。
5. 不清理其他任务的改动，不整目录复制两条路线的业务代码，不执行 `git add -A`。
6. 日常开发和本地验证属于已确定范围；涉及线上发布、替换稳定更新源、用户真实数据迁移等未纳入本轮实现。先把本地结果和证据做完整，再进入对应发布/迁移任务。
7. GitHub Issue 是项目正式跟踪入口；本地任务 ID 先用于本计划。需要发布成 Issues 时逐项建立映射，不自动评论用户问题或改已有 Issue 状态。
8. 不将计划、脚本存在或测试被跳过写成通过。done 必须有具体命令、退出码、产物和已知限制。
